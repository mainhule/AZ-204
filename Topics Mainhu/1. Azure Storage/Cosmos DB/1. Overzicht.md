# 📚 Azure Cosmos DB - Overzicht

## 🎯 Wat is Azure Cosmos DB?

Azure Cosmos DB is een **globally distributed**, **multi-model** NoSQL database service van Microsoft Azure. Het is ontworpen voor applicaties die **hoge beschikbaarheid**, **lage latency** en **elastische schaalbaarheid** nodig hebben over de hele wereld.

**Endpoint formaat:**
```
https://<account-name>.documents.azure.com:443/
```

### ⭐ Belangrijkste Kenmerken

| Kenmerk | Beschrijving |
|---------|--------------|
| **🌍 Global Distribution** | Replicate je data naar elke Azure regio met één klik. 99.999% availability voor multi-region databases |
| **📊 Multiple Data Models** | Ondersteunt Key-Value, Document, Column-family en Graph data formats |
| **⚡ Elastic Scalability** | Schaalt throughput en storage automatisch en onafhankelijk van elkaar |
| **🎚️ Consistency Levels** | Kies tussen 5 consistency levels om de trade-off tussen performance en data accuracy te maken |
| **📜 Comprehensive SLAs** | Gedekte SLAs voor latency, throughput, consistency én availability |

## 🏛️ Core Components - Hiërarchie

Azure Cosmos DB heeft een duidelijke hiërarchische structuur:

```
┌─────────────────────────────────────┐
│   📦 Cosmos DB Account              │
│   (Unit of distribution & billing)  │
│                                     │
│   ┌─────────────────────────────┐  │
│   │   🗄️ Database               │  │
│   │   (Namespace for containers)│  │
│   │                             │  │
│   │   ┌─────────────────────┐   │  │
│   │   │  📊 Container       │   │  │
│   │   │  (Schema-agnostic)  │   │  │
│   │   │                     │   │  │
│   │   │  ┌──────────────┐   │   │  │
│   │   │  │ 📄 Items     │   │   │  │
│   │   │  │ (Documents)  │   │   │  │
│   │   │  └──────────────┘   │   │  │
│   │   └─────────────────────┘   │  │
│   └─────────────────────────────┘  │
└─────────────────────────────────────┘
```

### 1️⃣ Cosmos DB Account

**Functie:** Top-level resource die alle databases beheert. Vergelijkbaar met een Storage Account voor containers.

**Belangrijke eigenschappen:**
- Globally unique DNS naam
- Unit of distribution en billing
- Consistentie level configuratie
- Regio configuratie (single/multi-region)
- **⚠️ Beperking:** Slechts **één Free Tier account** per Azure subscription

**Wanneer te gebruiken:**
- Eén account per applicatie of workload
- Gescheiden accounts voor development, testing en production

---

### 2️⃣ Database

**Functie:** Logische **namespace** voor het organiseren van containers.

**Belangrijke eigenschappen:**
- Bevat één of meerdere containers
- Beheert users, permissions en roles
- Kan throughput delen tussen containers (shared throughput mode)
- Minimum naam lengte: 3 karakters, alfanumeriek

**Throughput modellen:**
- **Database-level throughput:** Containers delen RUs
- **Container-level throughput:** Elke container heeft dedicated RUs

---

### 3️⃣ Container

**Functie:** De primaire **unit of scalability** voor zowel throughput als storage.

**Belangrijke eigenschappen:**
- **Schema-agnostic:** Geen vaste schema vereist
- **Partition key:** Vereist voor data distributie (altijd met `/` prefix, bijv. `/userId`)
- **Automatic indexing:** Alle properties worden automatisch geïndexeerd
- Data wordt verdeeld over meerdere **physical partitions**
- Horizontal scaling gebeurt automatisch

**Belangrijke concepten:**
- **Logical Partition:** Groep van items met dezelfde partition key (max 20 GB)
- **Physical Partition:** Fysieke resource die logical partitions host (max 10,000 RU/s)

---

### 4️⃣ Items

**Functie:** De kleinste **read/write unit** in een container.

**Belangrijke eigenschappen:**
- **Schema-agnostic:** Elk item kan een andere structuur hebben
- **API-dependent:** Representatie hangt af van gekozen API
  - NoSQL API: JSON documents
  - MongoDB API: BSON documents
  - Gremlin API: Graph nodes/edges
  - Cassandra API: Rows
  - Table API: Key-value pairs
- **Automatic indexing:** Alle properties worden geïndexeerd zonder expliciete index management
- Elke item moet een unieke `id` hebben binnen zijn partition

**Systeem properties:**
- `_rid`: Resource ID (system-generated)
- `_ts`: Timestamp van laatste modificatie
- `_self`: Self-link naar het item
- `_etag`: Voor optimistic concurrency control

## ⏱️ Time to Live (TTL)

**Functie:** Automatisch verwijderen van items na een bepaalde tijd.

### Hoe werkt TTL?

TTL specificeert hoeveel **seconden** een item moet worden bewaard sinds de **laatste modificatie**. Na deze periode wordt het item automatisch verwijderd zonder extra kosten (gebruikt spare RUs).

### 📍 TTL Configuratie Levels

| Level | Beschrijving | Prioriteit |
|-------|--------------|-----------|
| **Container-level** | Default TTL voor alle items in container | Laag |
| **Item-level** | Specifieke TTL per item | Hoog (overschrijft container) |

### ⚙️ Configuratie Opties

**Container-level TTL:**
- **Niet ingesteld of `-1`:** Items verlopen **nooit** (tenzij item-level TTL is ingesteld)
- **`null`:** TTL is **uitgeschakeld** - items verlopen nooit
- **Positief getal:** Default TTL in seconden voor alle items

**Item-level TTL:**
- **Niet ingesteld:** Item gebruikt container-level TTL
- **`-1`:** Item verloopt **nooit** (zelfs als container TTL heeft)
- **Positief getal:** Item verloopt na X seconden sinds laatste update

### 💡 Belangrijke Details

**Verwijdering gedrag:**
- Verwijdering gebeurt **op de achtergrond** met spare RUs
- Bij **lage RU capaciteit** kan verwijdering vertragen
- **Verlopen items** zijn **niet zichtbaar** in queries (zelfs als nog niet verwijderd)

**Performance overwegingen:**
- Geen extra RU kosten voor TTL verwijdering (gebruikt spare capacity)
- Bij hoge write workloads kunnen verwijderingen achterlopen
- Monitor container metrics om verwijderings-lag te detecteren

## 💻 Voorbeelden - Core Components

### Azure CLI

```bash
# Variabelen
account="mycosmosaccount"
database="mydatabase"
container="mycontainer"

# 1️⃣ Create Cosmos DB Account
az cosmosdb create \
  --name $account \
  --kind GlobalDocumentDB \
  --resource-group myResourceGroup \
  --locations regionName=westeurope failoverPriority=0 \
  --default-consistency-level Session

# 2️⃣ Create Database
az cosmosdb sql database create \
  --account-name $account \
  --name $database

# 3️⃣ Create Container met partition key
az cosmosdb sql container create \
  --account-name $account \
  --database-name $database \
  --name $container \
  --partition-key-path "/userId" \
  --throughput 400

# 4️⃣ Create Item (document)
az cosmosdb sql container item create \
  --account-name $account \
  --database-name $database \
  --container-name $container \
  --value "{\"id\": \"1\", \"userId\": \"user123\", \"name\": \"John Doe\", \"email\": \"john@example.com\"}"

# ⏱️ Container TTL instellen (30 dagen)
az cosmosdb sql container update \
  --account-name $account \
  --database-name $database \
  --name $container \
  --ttl 2592000
```

### C# (.NET SDK)

```csharp
using Microsoft.Azure.Cosmos;

// CosmosClient initialisatie (herbruikbaar, singleton pattern)
var cosmosClient = new CosmosClient(
    accountEndpoint: "https://mycosmosaccount.documents.azure.com:443/",
    authKeyOrResourceToken: "<primary-key>"
);

// Optioneel: CosmosClientOptions voor advanced configuratie
var options = new CosmosClientOptions
{
    ApplicationName = "MyApp",
    ConnectionMode = ConnectionMode.Direct, // Direct mode voor beste performance
    ConsistencyLevel = ConsistencyLevel.Session
};
var cosmosClient = new CosmosClient("<connection-string>", options);

// ========================================
// 1️⃣ Database Operations
// ========================================

// Create database
Database database = await cosmosClient.CreateDatabaseIfNotExistsAsync(
    id: "mydatabase",
    throughput: 400 // Optioneel: shared throughput tussen containers
);

// Get database reference
database = cosmosClient.GetDatabase("mydatabase");

// Read database (re-fetch metadata)
DatabaseResponse response = await database.ReadAsync();
Console.WriteLine($"Database RU: {response.RequestCharge}");

// ========================================
// 2️⃣ Container Operations
// ========================================

// Create container met partition key
Container container = await database.CreateContainerIfNotExistsAsync(
    id: "mycontainer",
    partitionKeyPath: "/userId",
    throughput: 400 // Dedicated throughput voor deze container
);

// Create container met TTL (30 dagen)
var containerProperties = new ContainerProperties
{
    Id = "mycontainer",
    PartitionKeyPath = "/userId",
    DefaultTimeToLive = 2592000 // 30 dagen in seconden
};
container = await database.CreateContainerIfNotExistsAsync(containerProperties, 400);

// Get container reference
container = database.GetContainer("mycontainer");

// ========================================
// 3️⃣ Item (CRUD) Operations
// ========================================

// Define item class
public class User
{
    public string id { get; set; }
    public string userId { get; set; } // Partition key
    public string name { get; set; }
    public string email { get; set; }
    public int? ttl { get; set; } // Item-level TTL (optioneel)
}

// CREATE: Item aanmaken
var newUser = new User
{
    id = "1",
    userId = "user123",
    name = "John Doe",
    email = "john@example.com"
};

ItemResponse<User> createResponse = await container.CreateItemAsync(
    item: newUser,
    partitionKey: new PartitionKey("user123")
);
Console.WriteLine($"Created item. RU: {createResponse.RequestCharge}");

// CREATE: Item met specifieke TTL (1 uur)
var tempUser = new User
{
    id = "2",
    userId = "user456",
    name = "Jane Doe",
    email = "jane@example.com",
    ttl = 3600 // Verloopt over 1 uur
};
await container.CreateItemAsync(tempUser, new PartitionKey("user456"));

// READ: Item ophalen (point read - meest efficiënt)
ItemResponse<User> readResponse = await container.ReadItemAsync<User>(
    id: "1",
    partitionKey: new PartitionKey("user123")
);
User user = readResponse.Resource;
Console.WriteLine($"Read item. RU: {readResponse.RequestCharge}");

// UPDATE: Item vervangen
user.email = "newemail@example.com";
ItemResponse<User> updateResponse = await container.ReplaceItemAsync(
    item: user,
    id: user.id,
    partitionKey: new PartitionKey(user.userId)
);

// DELETE: Item verwijderen
await container.DeleteItemAsync<User>(
    id: "1",
    partitionKey: new PartitionKey("user123")
);

// ========================================
// 4️⃣ Querying Items
// ========================================

// Simple query
QueryDefinition query = new QueryDefinition(
    "SELECT * FROM c WHERE c.userId = @userId"
).WithParameter("@userId", "user123");

FeedIterator<User> iterator = container.GetItemQueryIterator<User>(query);

List<User> results = new List<User>();
while (iterator.HasMoreResults)
{
    FeedResponse<User> response = await iterator.ReadNextAsync();
    results.AddRange(response);
    Console.WriteLine($"Query RU: {response.RequestCharge}");
}

// Query met partition key (meest efficiënt)
var queryWithPartitionKey = new QueryDefinition(
    "SELECT * FROM c WHERE c.email CONTAINS @domain"
).WithParameter("@domain", "example.com");

iterator = container.GetItemQueryIterator<User>(
    queryDefinition: queryWithPartitionKey,
    requestOptions: new QueryRequestOptions
    {
        PartitionKey = new PartitionKey("user123"), // Query binnen één partition
        MaxItemCount = 10 // Page size
    }
);

// ========================================
// 5️⃣ Dynamic Items (geen class definitie)
// ========================================

dynamic dynamicItem = new
{
    id = "3",
    userId = "user789",
    customField = "custom value",
    nested = new { property = "nested value" }
};

await container.CreateItemAsync(dynamicItem, new PartitionKey("user789"));

// Read als dynamic
ItemResponse<dynamic> dynamicResponse = await container.ReadItemAsync<dynamic>(
    id: "3",
    partitionKey: new PartitionKey("user789")
);
dynamic retrievedItem = dynamicResponse.Resource;
Console.WriteLine(retrievedItem.customField);
```

## 🎯 Naamgeving Conventies

**Belangrijke regels:**
- **Minimum lengte:** 3 karakters voor alle resources (account, database, container)
- **Toegestane karakters:** Alfanumeriek, underscores, hyphens
- **Partition keys:** Altijd met **`/`** prefix (bijvoorbeeld: `/userId`, `/category`, `/tenantId`)
- **Item IDs:** Moet uniek zijn **binnen de partition** (niet globally uniek)

## 📌 Best Practices

### ✅ Do's

| Praktijk | Reden |
|----------|-------|
| **Gebruik descriptieve partition keys** | Bijvoorbeeld `/userId` ipv `/pk` voor betere leesbaarheid |
| **Plan partition key strategy vooraf** | Kan niet worden gewijzigd na container creatie |
| **Gebruik container-level TTL voor algemene data** | Bijvoorbeeld logs, temporary data, cache entries |
| **Hergebruik CosmosClient instance** | Singleton pattern voorkomt connection overhead |
| **Enable automatic indexing** | Is standaard aan en zorgt voor fast queries |
| **Gebruik point reads wanneer mogelijk** | ReadItemAsync met id + partition key is goedkoopst (1 RU voor 1KB item) |

### ❌ Don'ts

| Anti-pattern | Waarom niet? |
|--------------|---------------|
| **Wijzigen partition key na creation** | Niet mogelijk - vereist data migratie naar nieuwe container |
| **Te weinig unieke partition key waarden** | Creëert "hot partitions" met performance bottlenecks |
| **TTL gebruiken voor mission-critical data** | Verwijdering kan vertragen bij lage RUs |
| **Elk item een eigen TTL geven** | Gebruik container-level TTL waar mogelijk voor consistency |
| **Grote items (> 2 MB)** | Hogere RU kosten en langzame queries |
| **Negeren van RU charges** | Monitor query costs om expensive queries te identificeren |
