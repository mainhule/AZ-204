## 🔌 1. Connectivity Modes

Cosmos DB ondersteunt **twee connectivity modes** die bepalen hoe je SDK communiceert met de service.

### 🌐 Gateway Mode (⏺️ Default)

**💡 Omschrijving:**  
Alle requests gaan via een **HTTPS gateway** endpoint.

| Aspect | Details |
|--------|---------|
| **Protocol** | HTTPS (port 443) |
| **Endpoints** | Single DNS endpoint |
| **Firewall** | ✅ Gemakkelijk (alleen port 443) |
| **Performance** | 🟡 Matig (extra hop via gateway) |
| **Socket connections** | 🟢 Laag (shared connections) |

**✅ Gebruik wanneer:**
- Corporate networks met strikte firewall regels
- Beperkt aantal socket connections beschikbaar
- Testing/development omgevingen

---

### ⚡ Direct Mode

**💡 Omschrijving:**  
Directe **TCP connecties** naar Cosmos DB backend nodes.

| Aspect | Details |
|--------|---------|
| **Protocol** | TCP met TLS encryption |
| **Endpoints** | Multiple endpoints (direct naar partitions) |
| **Firewall** | ⚠️ Vereist extra ports (10250-10255) |
| **Performance** | ⚡ **Beste** (laagste latency) |
| **Socket connections** | 🔴 Hoog (direct connections per partition) |

**✅ Gebruik wanneer:**
- **Production workloads** met lage latency requirements
- Performance is kritiek
- Geen strikte firewall beperkingen

---

### 💻 Code Configuratie

```csharp
using Microsoft.Azure.Cosmos;

// ========================================
// Gateway Mode (default)
// ========================================
var gatewayOptions = new CosmosClientOptions
{
    ConnectionMode = ConnectionMode.Gateway,
    // HTTPS port 443
};
var gatewayClient = new CosmosClient("<endpoint>", "<key>", gatewayOptions);

// ========================================
// Direct Mode (best performance)
// ========================================
var directOptions = new CosmosClientOptions
{
    ConnectionMode = ConnectionMode.Direct,
    // TCP met TLS, ports 10250-10255
    MaxRequestsPerTcpConnection = 30,
    MaxTcpConnectionsPerEndpoint = 65535
};
var directClient = new CosmosClient("<endpoint>", "<key>", directOptions);
```

## ⚡ 2. Performance Best Practices

### 🎯 SDK Configuration

```csharp
// Optimal CosmosClient configuration
var options = new CosmosClientOptions
{
    // 1. Connectivity
    ConnectionMode = ConnectionMode.Direct, // ⚡ Best performance
    
    // 2. Application region (co-location)
    ApplicationRegion = Regions.WestEurope, // Same region as database
    
    // 3. Consistency
    ConsistencyLevel = ConsistencyLevel.Session, // Default, good balance
    
    // 4. Retry policy (voor throttling)
    MaxRetryAttemptsOnRateLimitedRequests = 9,
    MaxRetryWaitTimeOnRateLimitedRequests = TimeSpan.FromSeconds(30),
    
    // 5. Bulk support (voor batch writes)
    AllowBulkExecution = true,
    
    // 6. Request timeout
    RequestTimeout = TimeSpan.FromSeconds(60)
};

var cosmosClient = new CosmosClient("<endpoint>", "<key>", options);
```

---

### 📍 1. Co-location (Same Region)

**✅ Best Practice:**  
Plaats je applicatie in **dezelfde Azure regio** als je Cosmos DB account.

```
❌ Bad: App in West Europe, Cosmos DB in East US
   Latency: ~100-150ms

✅ Good: App in West Europe, Cosmos DB in West Europe
   Latency: ~5-15ms

Performance improvement: 10x-20x beter!
```

---

### 📦 2. Bulk Operations

```csharp
// ========================================
// Bulk Write Operations
// ========================================

// Enable bulk execution
var options = new CosmosClientOptions { AllowBulkExecution = true };
var client = new CosmosClient("<endpoint>", "<key>", options);
var container = client.GetContainer("database", "container");

// Batch insert
var tasks = new List<Task>();
foreach (var item in items) // Bijvoorbeeld 1000+ items
{
    tasks.Add(container.CreateItemAsync(item, new PartitionKey(item.partitionKey)));
}

await Task.WhenAll(tasks);
// Veel sneller dan sequential inserts!
```

---

### 🔍 3. Point Reads (Preferred)

```csharp
// ✅ Best: Point read (ReadItemAsync)
// Cost: ~1 RU voor 1KB item
ItemResponse<Product> response = await container.ReadItemAsync<Product>(
    id: "product-123",
    partitionKey: new PartitionKey("Electronics")
);

// ❌ Avoid: Query zelfs met id filter
// Cost: ~3-10 RU
var query = new QueryDefinition("SELECT * FROM c WHERE c.id = @id")
    .WithParameter("@id", "product-123");
```

---

### 📝 4. Minimize Response Content

```csharp
// Bij writes: Disable response content als je het item niet nodig hebt
ItemResponse<Product> response = await container.CreateItemAsync(
    item: product,
    requestOptions: new ItemRequestOptions
    {
        EnableContentResponseOnWrite = false // Scheelt ~50% RU
    }
);

// Response bevat geen content, maar wel status + headers
Console.WriteLine($"Status: {response.StatusCode}");
Console.WriteLine($"RU: {response.RequestCharge}");
```

---

### 🗂️ 5. Exclude Unused Paths from Indexing

```csharp
// Bij container creatie: Exclude large fields
var containerProperties = new ContainerProperties
{
    Id = "products",
    PartitionKeyPath = "/category",
    IndexingPolicy = new IndexingPolicy
    {
        ExcludedPaths =
        {
            new ExcludedPath { Path = "/description/*" },
            new ExcludedPath { Path = "/largeBlob/*" },
            new ExcludedPath { Path = "/reviews/*/comment/*" }
        }
    }
};

// Write RU cost daalt significant!
```

---

### 🔄 6. Connection Pool (Singleton Pattern)

```csharp
// ✅ GOOD: Single CosmosClient instance (singleton)
public class CosmosService
{
    private static readonly Lazy<CosmosClient> _client = new Lazy<CosmosClient>(() =>
    {
        return new CosmosClient("<endpoint>", "<key>", new CosmosClientOptions
        {
            ConnectionMode = ConnectionMode.Direct
        });
    });

    public static CosmosClient Client => _client.Value;
}

// ❌ BAD: Nieuwe CosmosClient per request
// Dit verspilt socket connections!
public async Task<Product> GetProduct(string id)
{
    var client = new CosmosClient("<endpoint>", "<key>"); // ❌ Anti-pattern
    var container = client.GetContainer("db", "container");
    return await container.ReadItemAsync<Product>(id, new PartitionKey(id));
}
```

## 🌍 3. Global Distribution

Azure Cosmos DB kan data **repliceren** naar meerdere Azure regio's voor lage latency wereldwijd.

### 📊 Multi-region Features

| Feature | Beschrijving |
|---------|--------------|
| **Multi-region reads** | Data wordt gerepliceerd naar alle regio's |
| **Multi-region writes** | Schrijf naar ELKE regio (active-active) |
| **Automatic failover** | Bij regio uitval automatische failover |
| **Manual failover** | Voor testing disaster recovery |
| **No downtime** | Regio's toevoegen/verwijderen zonder downtime |

---

### 💻 Multi-region Configuration

```bash
# Add region via CLI
az cosmosdb update \
  --name mycosmosaccount \
  --resource-group myResourceGroup \
  --locations regionName=westeurope failoverPriority=0 \
  --locations regionName=eastus failoverPriority=1 \
  --locations regionName=southeastasia failoverPriority=2

# Enable multi-region writes
az cosmosdb update \
  --name mycosmosaccount \
  --resource-group myResourceGroup \
  --enable-multiple-write-locations true
```

```csharp
// C# SDK: Preferred region configuration
var options = new CosmosClientOptions
{
    ApplicationRegion = Regions.WestEurope, // Primaire regio
    // Of gebruik ApplicationPreferredRegions voor fallback lijst
    ApplicationPreferredRegions = new List<string>
    {
        Regions.WestEurope,      // 1st choice
        Regions.NorthEurope,     // 2nd choice (fallback)
        Regions.EastUS           // 3rd choice
    }
};
```

---

### 🔄 Automatic Failover

```
Setup:
Region 1: West Europe (priority 0 - primary)
Region 2: East US (priority 1 - secondary)
Region 3: Southeast Asia (priority 2)

Scenario: West Europe gaat down
→ Automatic failover naar East US
→ Applicaties blijven beschikbaar
→ Geen downtime (seamless)

Recovery: West Europe komt terug online
→ Automatisch herstel naar primary
```

---

### 🧪 Manual Failover (Testing)

```bash
# Trigger manual failover voor testing
az cosmosdb failover-priority-change \
  --name mycosmosaccount \
  --resource-group myResourceGroup \
  --failover-policies eastus=0 westeurope=1

# Test je applicatie disaster recovery procedures
```

## ⚔️ 4. Conflict Resolution

Bij **multi-region writes** kunnen **write conflicts** ontstaan wanneer hetzelfde item tegelijkertijd in meerdere regio's wordt gewijzigd.

### 🎯 Conflict Resolution Policies

| Policy | Beschrijving |
|--------|--------------|
| **Last Writer Wins (LWW)** ⏺️ | Laatste write (op basis van timestamp) wint |
| **Custom (Stored Procedure)** | Je eigen conflict resolution logica |

⚠️ **Belangrijk:**  
Conflict resolution policy kan **alleen bij container creatie** worden ingesteld (immutable).

---

### 💻 LWW (Last Writer Wins) - Default

```csharp
// Default: Uses _ts (system timestamp) property
var containerProperties = new ContainerProperties
{
    Id = "products",
    PartitionKeyPath = "/category",
    ConflictResolutionPolicy = new ConflictResolutionPolicy
    {
        Mode = ConflictResolutionMode.LastWriterWins,
        ResolutionPath = "/_ts" // Default: system timestamp
    }
};

await database.CreateContainerAsync(containerProperties);
```

**Custom timestamp property:**
```csharp
// Use custom property voor LWW
var policy = new ConflictResolutionPolicy
{
    Mode = ConflictResolutionMode.LastWriterWins,
    ResolutionPath = "/myCustomTimestamp" // Your custom timestamp field
};
```

---

### 💻 Custom Conflict Resolution (Stored Procedure)

```javascript
// Stored procedure: customConflictResolver.js
function customConflictResolver(conflictingItems, conflictingItemsContinuation, isBatchPartitioned) {
    var context = getContext();
    var container = context.getCollection();
    var response = context.getResponse();

    // conflictingItems bevat alle conflicting versies
    // Bijvoorbeeld: Merge logic, highest value wins, etc.

    // Custom logic: Choose item met hoogste prijs
    var winner = conflictingItems[0];
    for (var i = 1; i < conflictingItems.length; i++) {
        if (conflictingItems[i].price > winner.price) {
            winner = conflictingItems[i];
        }
    }

    // Accept winner
    var accepted = container.replaceDocument(
        winner._self,
        winner,
        function(err, replacedDocument) {
            if (err) throw err;
            response.setBody(replacedDocument);
        }
    );

    if (!accepted) throw new Error("Unable to resolve conflict");
}
```

```csharp
// Register conflict resolution stored procedure
var containerProperties = new ContainerProperties
{
    Id = "products",
    PartitionKeyPath = "/category",
    ConflictResolutionPolicy = new ConflictResolutionPolicy
    {
        Mode = ConflictResolutionMode.Custom,
        ResolutionProcedure = "dbs/mydb/colls/products/sprocs/customConflictResolver"
    }
};

await database.CreateContainerAsync(containerProperties);
```

## 🔐 5. Security & Authentication

### 🔑 Authentication Methods

| Method | Use Case | Security Level |
|--------|----------|----------------|
| **Primary/Secondary Key** | Admin access | 🔴 Highest privileges |
| **Resource Tokens** | Granular access (item-level) | 🟡 Limited scope |
| **Azure AD (Entra ID)** | Identity-based access | 🟢 Best practice (RBAC) |

---

### 🗝️ Primary/Secondary Keys

```csharp
// Connection string met key
var cosmosClient = new CosmosClient(
    accountEndpoint: "https://myaccount.documents.azure.com:443/",
    authKeyOrResourceToken: "<primary-or-secondary-key>"
);

// Of connection string
var connectionString = "AccountEndpoint=https://...;AccountKey=<key>;";
var client = new CosmosClient(connectionString);
```

**⚠️ Security Risk:**  
Primary/Secondary keys hebben **volledige admin rechten**. Gebruik alleen in backend services, **nooit in client-side code**!

---

### 🎫 Azure AD (Entra ID) - Best Practice

```csharp
using Azure.Identity;
using Microsoft.Azure.Cosmos;

// Managed Identity (Azure resources)
var credential = new DefaultAzureCredential();
var client = new CosmosClient(
    accountEndpoint: "https://myaccount.documents.azure.com:443/",
    tokenCredential: credential
);

// Service Principal
var credential = new ClientSecretCredential(
    tenantId: "<tenant-id>",
    clientId: "<client-id>",
    clientSecret: "<client-secret>"
);
var client = new CosmosClient("<endpoint>", credential);
```

**RBAC Roles:**
- `Cosmos DB Built-in Data Reader` - Read-only access
- `Cosmos DB Built-in Data Contributor` - Read/write access
- `DocumentDB Account Contributor` - Manage account

---

### 🔒 Encryption

| Type | Details |
|------|---------|
| **At-rest** | Automatisch encrypted (Microsoft-managed keys 🔑 of customer-managed keys 🗝️) |
| **In-transit** | TLS 1.2+ voor alle connecties |
| **Client-side** | Optioneel: Encrypt data before sending |

---

### 🌐 Network Security

```bash
# Firewall rules (IP whitelist)
az cosmosdb update \
  --name mycosmosaccount \
  --resource-group myResourceGroup \
  --ip-range-filter "104.42.195.92,40.76.54.131,52.176.6.30"

# Virtual Network (VNet) integration
az cosmosdb update \
  --name mycosmosaccount \
  --resource-group myResourceGroup \
  --enable-virtual-network true \
  --virtual-network-rules "/subscriptions/.../subnets/mysubnet"

# Private Endpoint
az network private-endpoint create \
  --name cosmosPrivateEndpoint \
  --resource-group myResourceGroup \
  --vnet-name myVNet \
  --subnet mySubnet \
  --private-connection-resource-id "<cosmos-account-resource-id>" \
  --group-id Sql \
  --connection-name cosmosConnection
```

## 💾 6. Backup & Restore

Azure Cosmos DB maakt **automatische backups** van je data.

### 📊 Backup Modes

| Mode | Interval | Retention | Restore Process |
|------|----------|-----------|-----------------|
| **Periodic** ⏺️ | Customizable (min 1 uur) | Max 1 maand | Via Azure Support |
| **Continuous** | Real-time (point-in-time) | 7 of 30 dagen | Self-service via Portal |

---

### 🔄 Periodic Backup (Default)

**Karakteristieken:**
- Backups elke **X uren** (min 1 uur)
- Retention: max **1 maand**
- Backups zijn **encrypted** (Microsoft-managed keys)
- **Geen impact** op performance
- Restore via **Azure Support ticket**

```bash
# Configure periodic backup
az cosmosdb update \
  --name mycosmosaccount \
  --resource-group myResourceGroup \
  --backup-interval 240 \        # Elke 4 uur
  --backup-retention 720          # 30 dagen (in uren)
```

**⚠️ Restore Beperkingen:**
- Restore naar account in **dezelfde subscription**
- Account moet **zelfde of hogere** RU/s hebben
- Account moet **zelfde of meer** partitions hebben

---

### ⏱️ Continuous Backup

**Karakteristieken:**
- **Point-in-time restore** (elke seconde)
- Retention: **7 of 30 dagen**
- **Self-service restore** via Portal
- **Kan niet switchen** naar periodic mode

```bash
# Create account met continuous backup
az cosmosdb create \
  --name mycosmosaccount \
  --resource-group myResourceGroup \
  --backup-policy-type Continuous \
  --continuous-tier Continuous7Days    # Of Continuous30Days
```

**Self-service Restore:**
```bash
# Restore via CLI
az cosmosdb restore \
  --target-database-account-name restored-account \
  --account-name mycosmosaccount \
  --resource-group myResourceGroup \
  --restore-timestamp "2024-11-07T10:30:00Z" \
  --location westeurope
```

## 📊 7. Monitoring & Diagnostics

### 📈 Azure Monitor Metrics

**Belangrijke metrics:**

| Metric | Wat te monitoren |
|--------|------------------|
| **Total Request Units** | RU consumption over tijd |
| **Normalized RU Consumption** | % van provisioned RUs (>80% = scale up) |
| **Total Requests** | Aantal requests per seconde |
| **Throttled Requests (429)** | Rate-limited requests |
| **Availability** | % uptime |
| **Latency** | P50/P95/P99 latencies |

---

### 🔍 Diagnostic Logs

```bash
# Enable diagnostic settings
az monitor diagnostic-settings create \
  --name cosmosdb-diagnostics \
  --resource "<cosmos-account-resource-id>" \
  --logs '[{"category": "DataPlaneRequests", "enabled": true}]' \
  --metrics '[{"category": "AllMetrics", "enabled": true}]' \
  --workspace "<log-analytics-workspace-id>"
```

**Log Categories:**
- `DataPlaneRequests` - CRUD operations, queries
- `QueryRuntimeStatistics` - Query execution details
- `PartitionKeyStatistics` - Partition usage stats
- `ControlPlaneRequests` - Account management operations

---

### 💻 Application Insights Integration

```csharp
using Microsoft.ApplicationInsights;
using Microsoft.Azure.Cosmos;

var telemetryClient = new TelemetryClient();

// Track Cosmos DB operations
var stopwatch = System.Diagnostics.Stopwatch.StartNew();
ItemResponse<Product> response = await container.ReadItemAsync<Product>(id, partitionKey);
stopwatch.Stop();

telemetryClient.TrackDependency(
    dependencyTypeName: "Azure Cosmos DB",
    target: "mycosmosaccount",
    dependencyName: "ReadItem",
    data: $"Container: products, Id: {id}",
    startTime: DateTimeOffset.UtcNow.AddMilliseconds(-stopwatch.ElapsedMilliseconds),
    duration: stopwatch.Elapsed,
    resultCode: ((int)response.StatusCode).ToString(),
    success: response.StatusCode == System.Net.HttpStatusCode.OK
);

// Custom properties
var properties = new Dictionary<string, string>
{
    { "RequestCharge", response.RequestCharge.ToString() },
    { "PartitionKey", partitionKey.ToString() }
};
telemetryClient.TrackEvent("CosmosDBRead", properties);
```

### 🎯 Query Statistics

```csharp
// Enable query metrics
var query = new QueryDefinition("SELECT * FROM c WHERE c.category = @cat")
    .WithParameter("@cat", "Electronics");

FeedIterator<Product> iterator = container.GetItemQueryIterator<Product>(
    queryDefinition: query,
    requestOptions: new QueryRequestOptions
    {
        PopulateIndexMetrics = true
    }

    Console.WriteLine($"Response headers:");

    }
}
```
