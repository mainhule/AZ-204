# 🔍 Azure Cosmos DB - Querying (NoSQL API)

## 📖 Wat is Cosmos DB Query Language?

Azure Cosmos DB (NoSQL API) gebruikt een **SQL-achtige query taal** voor het opvragen van JSON documents. Het combineert de vertrouwdheid van SQL met de flexibiliteit van NoSQL.

### 🎯 Belangrijkste Kenmerken

| Kenmerk | Beschrijving |
|---------|--------------|
| **JSON-native** | Query rechtstreeks op JSON documents met nested properties |
| **SQL-like syntax** | Vertrouwde SELECT, FROM, WHERE, ORDER BY |
| **Case-sensitive** | Queries zijn hoofdlettergevoelig |
| **Automatic indexing** | Alle properties worden automatisch geïndexeerd |
| **No schema required** | Schema-less querying over variabele document structures |

---

## 📊 Data is Opgeslagen als JSON

```json
{
  "id": "product-123",
  "name": "Laptop",
  "category": "Electronics",
  "price": 999.99,
  "specifications": {
    "cpu": "Intel i7",
    "ram": "16GB",
    "storage": "512GB SSD"
  },
  "tags": ["laptop", "portable", "business"],
  "reviews": [
    { "rating": 5, "comment": "Excellent!" },
    { "rating": 4, "comment": "Good value" }
  ],
  "_ts": 1699363200
}
```

Je kunt alle properties (zelfs nested) direct querien zonder joins of complexe syntax.

## 🔤 Query Syntax Fundamentals

### 📌 Basis Regels

```sql
-- ✅ Column names vereisen alias (specifier)
SELECT c.name, c.price FROM c

-- ❌ Dit werkt NIET
SELECT name, price FROM c

-- ✅ FROM is alleen een alias (geen container naam nodig)
SELECT c.id FROM c  -- 'c' kan elke letter zijn

-- ✅ Case-sensitive
SELECT c.Name FROM c  -- Returnt items met property "Name"
SELECT c.name FROM c  -- Returnt items met property "name" (verschillend!)
```

**💡 Belangrijke verschillen met SQL:**
- `FROM` clause is **geen container naam**, maar een **alias**
- **Geen JOIN tussen containers** (alleen binnen een document)
- **Geen aggregation functies** zoals SUM(), AVG(), COUNT() (beperkt ondersteund)

## 🎯 Basic Query Examples

### Voorbeeld 1: Select All

```sql
-- Alle items returnen
SELECT * FROM c
```

```csharp
// C# SDK
var query = new QueryDefinition("SELECT * FROM c");
FeedIterator<Product> iterator = container.GetItemQueryIterator<Product>(query);

List<Product> results = new List<Product>();
while (iterator.HasMoreResults)
{
    FeedResponse<Product> response = await iterator.ReadNextAsync();
    results.AddRange(response);
    Console.WriteLine($"RU charge: {response.RequestCharge}");
}
```

---

### Voorbeeld 2: Projection (Specifieke velden)

```sql
-- Selecteer alleen specifieke properties
SELECT c.id, c.name, c.price FROM c
```

**💰 Cost Optimization:**  
Projection vermindert de hoeveelheid data die wordt getransfereerd, wat RU kosten kan verlagen!

---

### Voorbeeld 3: WHERE Clause (Filtering)

```sql
-- Filter op simple property
SELECT * FROM c WHERE c.category = "Electronics"

-- Multiple conditions
SELECT * FROM c 
WHERE c.category = "Electronics" 
  AND c.price < 1000

-- IN operator
SELECT * FROM c 
WHERE c.category IN ("Electronics", "Computers")

-- LIKE operator (pattern matching)
SELECT * FROM c 
WHERE STARTSWITH(c.name, "Lap")
```

```csharp
// C# SDK met parameters (best practice)
var query = new QueryDefinition(
    "SELECT * FROM c WHERE c.category = @category AND c.price < @maxPrice"
)
.WithParameter("@category", "Electronics")
.WithParameter("@maxPrice", 1000);

FeedIterator<Product> iterator = container.GetItemQueryIterator<Product>(query);
```

---

### Voorbeeld 4: Nested Properties

```sql
-- Query nested properties met dot notation
SELECT 
    c.id, 
    c.name, 
    c.specifications.cpu, 
    c.specifications.ram
FROM c
WHERE c.specifications.ram = "16GB"
```

---

### Voorbeeld 5: Array Properties

```sql
-- ARRAY_CONTAINS: Check of array een value bevat
SELECT * FROM c 
WHERE ARRAY_CONTAINS(c.tags, "laptop")

-- ARRAY_LENGTH: Lengte van array
SELECT c.id, ARRAY_LENGTH(c.reviews) AS reviewCount
FROM c
WHERE ARRAY_LENGTH(c.reviews) > 0
```

## 🔗 JOINs (Binnen Document)

**⚠️ Belangrijk:**  
Cosmos DB ondersteunt **GEEN JOINs tussen containers**. JOINs zijn alleen mogelijk **binnen één document** (bijv. array properties).

### Voorbeeld: JOIN met Array

```sql
-- JOIN op reviews array
SELECT 
    c.id,
    c.name,
    r.rating,
    r.comment
FROM c
JOIN r IN c.reviews
WHERE r.rating >= 4

-- Result:
-- [
--   { "id": "product-123", "name": "Laptop", "rating": 5, "comment": "Excellent!" },
--   { "id": "product-123", "name": "Laptop", "rating": 4, "comment": "Good value" }
-- ]
```

### Voorbeeld: Nested JOIN

```sql
-- JOIN op nested array binnen array
SELECT 
    c.name,
    p.color,
    t.value AS tag
FROM c
JOIN p IN c.variants
JOIN t IN p.tags
WHERE t.value = "popular"
```

## 🎨 Projections & Transformations

### VALUE Keyword (Flattening)

```sql
-- Zonder VALUE: Returnt object met property names
SELECT c.name, c.price FROM c

-- Result:
-- [
--   { "name": "Laptop", "price": 999.99 },
--   { "name": "Mouse", "price": 29.99 }
-- ]

-- Met VALUE: Returnt alleen de waarde
SELECT VALUE c.name FROM c

-- Result:
-- [
--   "Laptop",
--   "Mouse"
-- ]

-- VALUE met object literal
SELECT VALUE {
    "productName": c.name,
    "priceUSD": c.price,
    "vendor": c.manufacturer.name
}
FROM c

-- Result:
-- [
--   { "productName": "Laptop", "priceUSD": 999.99, "vendor": "TechCorp" }
-- ]
```

---

### Aliasing

```sql
-- Custom property names met AS
SELECT 
    c.id AS productId,
    c.name AS productName,
    c.price AS priceUSD,
    c.price * 0.9 AS discountedPrice
FROM c
```

## 📊 Aggregation & Functions

### COUNT

```sql
-- Count aantal items (returnt single value)
SELECT VALUE COUNT(1) FROM c

-- Count met filter
SELECT VALUE COUNT(1) FROM c 
WHERE c.category = "Electronics"
```

```csharp
// C# SDK
var query = new QueryDefinition("SELECT VALUE COUNT(1) FROM c WHERE c.category = @cat")
    .WithParameter("@cat", "Electronics");

FeedIterator<int> iterator = container.GetItemQueryIterator<int>(query);
int count = 0;
while (iterator.HasMoreResults)
{
    FeedResponse<int> response = await iterator.ReadNextAsync();
    count = response.FirstOrDefault();
}
Console.WriteLine($"Count: {count}");
```

**⚠️ Beperking:**  
Advanced aggregations (SUM, AVG, MIN, MAX, GROUP BY) zijn **zeer beperkt** ondersteund in Cosmos DB. Voor complexe aggregaties overweeg:
- Client-side aggregation
- Materialized views via Change Feed
- Azure Synapse Link (analytics)

## 🔧 Built-in Functions

### String Functions

```sql
-- STARTSWITH, ENDSWITH, CONTAINS
SELECT * FROM c 
WHERE STARTSWITH(c.name, "Lap")

SELECT * FROM c 
WHERE CONTAINS(c.name, "book")

-- UPPER, LOWER
SELECT UPPER(c.name) AS upperName FROM c

-- CONCAT
SELECT CONCAT(c.firstName, " ", c.lastName) AS fullName FROM c

-- LENGTH
SELECT c.name, LENGTH(c.name) AS nameLength FROM c
WHERE LENGTH(c.name) > 10
```

---

### Math Functions

```sql
-- ROUND, CEILING, FLOOR
SELECT 
    c.price,
    ROUND(c.price) AS roundedPrice,
    CEILING(c.price) AS ceilingPrice,
    FLOOR(c.price) AS floorPrice
FROM c

-- ABS, SQRT, POWER
SELECT 
    c.temperature,
    ABS(c.temperature) AS absoluteTemp,
    SQRT(c.value) AS sqrtValue,
    POWER(c.value, 2) AS squaredValue
FROM c
```

---

### Array Functions

```sql
-- ARRAY_LENGTH
SELECT c.id, ARRAY_LENGTH(c.tags) AS tagCount FROM c

-- ARRAY_CONTAINS
SELECT * FROM c 
WHERE ARRAY_CONTAINS(c.tags, "featured")

-- ARRAY_SLICE (substring van array)
SELECT c.id, ARRAY_SLICE(c.tags, 0, 2) AS firstTwoTags FROM c
```

---

### Type Checking

```sql
-- IS_DEFINED, IS_NULL, IS_NUMBER, IS_STRING, IS_BOOL, IS_ARRAY, IS_OBJECT
SELECT * FROM c 
WHERE IS_DEFINED(c.discountPrice)

SELECT * FROM c 
WHERE NOT IS_NULL(c.category)

SELECT * FROM c 
WHERE IS_NUMBER(c.price) AND c.price > 0
```

## 📑 Sorting & Pagination

### ORDER BY

```sql
-- Ascending (default)
SELECT * FROM c 
ORDER BY c.price

-- Descending
SELECT * FROM c 
ORDER BY c.price DESC

-- Multiple columns
SELECT * FROM c 
ORDER BY c.category, c.price DESC
```

**⚠️ Composite Index Required:**  
Queries met `ORDER BY` op **2+ properties** vereisen een **composite index**!

---

### OFFSET LIMIT (Pagination)

```sql
-- Skip eerste 10 items, neem volgende 20
SELECT * FROM c 
ORDER BY c.name
OFFSET 10 LIMIT 20

-- Page 1: OFFSET 0 LIMIT 20
-- Page 2: OFFSET 20 LIMIT 20
-- Page 3: OFFSET 40 LIMIT 20
```

## 🏎️ Performance & Indexing

### Automatic Indexing

**✅ Default Behavior:**  
Cosmos DB **indexeert automatisch** alle properties in alle documents.

**Voordelen:**
- Fast queries zonder manual index management
- Flexible schema changes

**Nadelen:**
- Write operations kosten meer RUs (indexing overhead)
- Storage overhead

---

### Indexing Policy Configuration

```csharp
// Customize indexing policy bij container creatie
var containerProperties = new ContainerProperties
{
    Id = "products",
    PartitionKeyPath = "/category",
    IndexingPolicy = new IndexingPolicy
    {
        Automatic = true,
        IndexingMode = IndexingMode.Consistent, // Of IndexingMode.None
        
        // Include specific paths
        IncludedPaths =
        {
            new IncludedPath { Path = "/*" } // Alle paths (default)
        },
        
        // Exclude paths die je nooit queried
        ExcludedPaths =
        {
            new ExcludedPath { Path = "/description/*" },
            new ExcludedPath { Path = "/largeBlob/*" }
        }
    }
};

await database.CreateContainerIfNotExistsAsync(containerProperties);
```

---

### Composite Indexes

**Wanneer nodig:**  
Queries met `ORDER BY` op **meerdere properties** of **complex filters**.

```json
{
  "indexingPolicy": {
    "compositeIndexes": [
      [
        { "path": "/category", "order": "ascending" },
        { "path": "/price", "order": "descending" }
      ],
      [
        { "path": "/name", "order": "ascending" },
        { "path": "/rating", "order": "descending" }
      ]
    ]
  }
}
```

```csharp
// C# SDK
var containerProperties = new ContainerProperties
{
    Id = "products",
    PartitionKeyPath = "/category",
    IndexingPolicy = new IndexingPolicy
    {
        CompositeIndexes =
        {
            new Collection<CompositePath>
            {
                new CompositePath { Path = "/category", Order = CompositePathSortOrder.Ascending },
                new CompositePath { Path = "/price", Order = CompositePathSortOrder.Descending }
            }
        }
    }
};
```

**Use case:**
```sql
-- Deze query vereist composite index
SELECT * FROM c 
ORDER BY c.category ASC, c.price DESC
```

## ⚡ Query Optimization Tips

### 1️⃣ Use Partition Key in WHERE

```sql
-- ✅ Single-partition query (goedkoopst)
SELECT * FROM c 
WHERE c.category = "Electronics" 
  AND c.price < 1000

-- Partition key: /category
-- RU cost: ~2-10 RU
```

```csharp
// C# SDK: Expliciet partition key meegeven
var query = new QueryDefinition(
    "SELECT * FROM c WHERE c.category = @cat AND c.price < @price"
)
.WithParameter("@cat", "Electronics")
.WithParameter("@price", 1000);

FeedIterator<Product> iterator = container.GetItemQueryIterator<Product>(
    queryDefinition: query,
    requestOptions: new QueryRequestOptions
    {
        PartitionKey = new PartitionKey("Electronics") // Blijft binnen één partition
    }
);
```

---

### 2️⃣ Avoid Cross-Partition Queries

```sql
-- ❌ Cross-partition query (duur)
SELECT * FROM c 
WHERE c.price < 1000

-- Scant ALLE partitions
-- RU cost: ~50-500+ RU (afhankelijk van aantal partitions)
```

**💡 Tip:** Als cross-partition queries niet te vermijden zijn, overweeg:
- Partition key redesign
- Denormalized views voor specifieke query patterns

---

### 3️⃣ Use Projections

```sql
-- ❌ Returnt alle properties (meer data transfer)
SELECT * FROM c WHERE c.category = "Electronics"

-- ✅ Returnt alleen benodigde properties
SELECT c.id, c.name, c.price 
FROM c 
WHERE c.category = "Electronics"

-- Kan 30-50% RU besparen!
```

---

### 4️⃣ Exclude Unused Paths from Indexing

```csharp
// Large fields die je nooit queried → exclude from index
containerProperties.IndexingPolicy.ExcludedPaths.Add(
    new ExcludedPath { Path = "/description/*" }
);
containerProperties.IndexingPolicy.ExcludedPaths.Add(
    new ExcludedPath { Path = "/reviews/*/comment/*" }
);

// Write RU cost daalt significant!
```

---

### 5️⃣ Use Point Reads When Possible

```csharp
// ❌ Query (ook met partition key)
var query = new QueryDefinition("SELECT * FROM c WHERE c.id = @id")
    .WithParameter("@id", "product-123");
// RU cost: ~3-5 RU

// ✅ Point read (ReadItemAsync)
ItemResponse<Product> response = await container.ReadItemAsync<Product>(
    id: "product-123",
    partitionKey: new PartitionKey("Electronics")
);
// RU cost: ~1 RU (10KB item)
```

## 📊 Query Metrics & Debugging

```csharp
// Enable query metrics voor debugging
var query = new QueryDefinition("SELECT * FROM c WHERE c.category = @cat")
    .WithParameter("@cat", "Electronics");

FeedIterator<Product> iterator = container.GetItemQueryIterator<Product>(
    queryDefinition: query,
    requestOptions: new QueryRequestOptions
    {
        PopulateIndexMetrics = true // Enable index metrics
    }
);

while (iterator.HasMoreResults)
{
    FeedResponse<Product> response = await iterator.ReadNextAsync();
    
    // RU charge
    Console.WriteLine($"RU charge: {response.RequestCharge}");
    
    // Index metrics
    Console.WriteLine($"Index metrics: {response.IndexMetrics}");
    
    // Continuation token (voor pagination)
    Console.WriteLine($"Continuation token: {response.ContinuationToken}");
}
```

## 🎯 Common Query Patterns

### Pattern 1: Search by Multiple Fields

```sql
SELECT * FROM c 
WHERE c.name LIKE '%laptop%' 
   OR c.description LIKE '%laptop%'
   OR ARRAY_CONTAINS(c.tags, "laptop")
```

---

### Pattern 2: Range Queries

```sql
SELECT * FROM c 
WHERE c.price BETWEEN 500 AND 1500
  AND c.rating >= 4

-- Equivalent:
SELECT * FROM c 
WHERE c.price >= 500 
  AND c.price <= 1500
  AND c.rating >= 4
```

---

### Pattern 3: Nested Object Filtering

```sql
SELECT * FROM c 
WHERE c.address.city = "Amsterdam"
  AND c.address.country = "Netherlands"
```

---

### Pattern 4: Array Filtering with JOIN

```sql
-- Get products met minstens één 5-star review
SELECT DISTINCT c.id, c.name
FROM c
JOIN r IN c.reviews
WHERE r.rating = 5
```

## 🏆 Best Practices

### ✅ Do's

| Praktijk | Reden |
|----------|-------|
| **Partition key in WHERE** | Voorkomt expensive cross-partition scans |
| **Use projections** | Vermindert data transfer en RU costs |
| **Point reads when possible** | ReadItemAsync is goedkoopste operatie |
| **Parameterized queries** | SQL injection prevention + query plan caching |
| **Exclude unused paths** | Lagere write RU costs |
| **Composite indexes voor ORDER BY** | Required voor multi-column sorting |
| **Monitor query metrics** | Identify expensive queries |

### ❌ Don'ts

| Anti-pattern | Waarom niet? |
|--------------|---------------|
| **SELECT * overal** | Verspilt RUs door ongebruikte data |
| **Cross-partition queries zonder noodzaak** | 10x-100x duurder dan single-partition |
| **String concatenation in queries** | SQL injection risico, geen query plan caching |
| **Complex aggregations** | Cosmos DB is geen analytics engine |
| **LIKE '%pattern%'** | Full scan, zeer duur |
| **ORDER BY zonder composite index** | Query fails of zeer duur |
