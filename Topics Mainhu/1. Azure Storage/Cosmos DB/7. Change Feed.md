# 📡 Azure Cosmos DB - Change Feed

## 📖 Wat is Change Feed?

**Change Feed** is een feature die een **persistent log** bijhoudt van alle wijzigingen in een container in **chronologische volgorde**. Het stelt applicaties in staat om realtime te reageren op data wijzigingen.

### 🎯 Belangrijkste Kenmerken

| Kenmerk | Beschrijving |
|---------|--------------|
| **Automatisch** | ✅ **Standaard enabled** voor alle containers |
| **Persistent** | Wijzigingen blijven beschikbaar voor consumption |
| **Ordered** | Chronologische volgorde **per partition key** |
| **Change types** | Alleen **inserts** en **updates** (geen deletes) |
| **Retention** | Geen expiratie - blijft beschikbaar totdat consumed |

---

## 🔄 Wat wordt Getrackt?

### ✅ Wordt Getrackt

### ❌ Wordt NIET Getrackt
  - **Workaround:** Soft delete met TTL (zie voorbeeld hieronder)

### 🆕 Nieuw: Deletes tracken met 'All Versions and Delete Mode'

Sinds 2023/2024 is er een nieuwe optie in Cosmos DB: **All Versions and Delete Mode**. Als je deze mode inschakelt voor een container, worden ook **deletes** zichtbaar in de change feed. Je ziet dan alle wijzigingen: create, update én delete.

**Standaard:** Alleen inserts en updates worden getrackt.
**Met All Versions and Delete Mode:** Ook deletes worden getrackt in de change feed.

Zie [Microsoft Docs](https://learn.microsoft.com/en-us/azure/cosmos-db/change-feed#all-versions-and-delete-mode) voor details en hoe je deze mode inschakelt.

### ⚙️ Ordering Garantie

```
Partition Key: "user-123"
├─ Change 1: Insert item A   (timestamp: 10:00:00)
├─ Change 2: Update item A   (timestamp: 10:00:05)
└─ Change 3: Insert item B   (timestamp: 10:00:10)

Partition Key: "user-456"
├─ Change 1: Insert item C   (timestamp: 10:00:02)
└─ Change 2: Update item C   (timestamp: 10:00:08)

✅ Ordering gegarandeerd BINNEN partition
❌ Ordering NIET gegarandeerd TUSSEN partitions
```

## 🎭 Twee Interaction Models

### 1️⃣ Push Model (⭐ Aanbevolen)

**💡 Omschrijving:**  
Change feed processor **pushed automatisch** wijzigingen naar je applicatie.

**✅ Voordelen:**
- **Automatisch** - Geen polling nodig
- **Schaalbaar** - Automatische load balancing over workers
- **Checkpoint management** - Automatisch progress tracking
- **Azure Functions integration** - Native support

**🎯 Use Cases:**
- **Event-driven architectures** - Reageer op data wijzigingen
- **Real-time sync** - Sync naar andere databases/services
- **Materialized views** - Denormalized read models
- **Data pipelines** - ETL/ELT processen

---

### 2️⃣ Pull Model

**💡 Omschrijving:**  
Je applicatie **pollt** actief de change feed voor nieuwe wijzigingen.

**✅ Voordelen:**
- **Volledige controle** - Bepaal zelf wanneer en hoeveel te lezen
- **Batch processing** - Verwerk wijzigingen in batches
- **Custom logic** - Flexibele verwerking

**🎯 Use Cases:**
- **Migration scenarios** - Eenmalige data migratie
- **Batch processing** - Periodieke verwerking
- **Custom scheduling** - Non-real-time processing
- **Testing & debugging** - Granulaire controle

## 🏗️ Change Feed Processor Architecture

De Change Feed Processor heeft 4 key components:

```
┌─────────────────────────────────────────────────┐
│         Change Feed Processor Architecture      │
├─────────────────────────────────────────────────┤
│                                                 │
│  1️⃣ Monitored Container                         │
│     └─ De container met wijzigingen             │
│                                                 │
│  2️⃣ Lease Container                             │
│     └─ Coordination & state management          │
│                                                 │
│  3️⃣ Compute Instance(s)                         │
│     └─ VM, Azure Function, App Service, etc.    │
│                                                 │
│  4️⃣ Delegate (Handler Function)                 │
│     └─ Je custom code om changes te verwerken   │
│                                                 │
└─────────────────────────────────────────────────┘
```

### 1️⃣ Monitored Container
De **source container** waar wijzigingen worden getrackt.

### 2️⃣ Lease Container
Een **aparte container** die:
- Progress (checkpoint) bijhoudt per partition
- **Load balancing** coördineert tussen workers
- **Failover** mogelijk maakt bij worker crashes

**⚠️ Belangrijk:**
- Kan in **hetzelfde** of **ander** Cosmos DB account
- Partition key: **Moet `/id` zijn**

### 3️⃣ Compute Instance
De **host** waar change feed processor draait:
- Azure Function
- Azure App Service
- Container/Kubernetes
- VM
- On-premises server

### 4️⃣ Delegate
Je **custom code** die change batches verwerkt.

## 💻 Change Feed Processor - Code Voorbeelden

### Voorbeeld 1: Basic Change Feed Processor

```csharp
using Microsoft.Azure.Cosmos;

// ========================================
// 1. Setup Cosmos Client & Containers
// ========================================

var cosmosClient = new CosmosClient("<endpoint>", "<key>");

// Monitored container (waar changes worden getrackt)
Container monitoredContainer = cosmosClient
    .GetContainer("databaseName", "monitoredContainerName");

// Lease container (voor progress tracking)
Container leaseContainer = cosmosClient
    .GetContainer("databaseName", "leaseContainerName");

// ========================================
// 2. Define Delegate (Handler)
// ========================================

static async Task HandleChangesAsync(
    ChangeFeedProcessorContext context,
    IReadOnlyCollection<MyItem> changes,
    CancellationToken cancellationToken)
{
    Console.WriteLine($"Processing {changes.Count} changes...");
    Console.WriteLine($"Lease token: {context.LeaseToken}");
    Console.WriteLine($"RU charge: {context.Headers.RequestCharge}");
    
    // Optional: Session token voor consistency
    Console.WriteLine($"Session token: {context.Headers.Session}");

    foreach (MyItem item in changes)
    {
        Console.WriteLine($"Change detected: {item.id} - {item.name}");
        
        // Custom processing logic
        await ProcessItemAsync(item);
    }
}

// ========================================
// 3. Build & Start Change Feed Processor
// ========================================

ChangeFeedProcessor changeFeedProcessor = monitoredContainer
    .GetChangeFeedProcessorBuilder<MyItem>(
        processorName: "myChangeFeedProcessor",
        onChangesDelegate: HandleChangesAsync)
    .WithInstanceName("consoleHost")  // Unique per compute instance
    .WithLeaseContainer(leaseContainer)
    .WithStartTime(DateTime.UtcNow.AddHours(-1))  // Optional: start vanaf 1 uur geleden
    .Build();

// Start processor
Console.WriteLine("Starting Change Feed Processor...");
await changeFeedProcessor.StartAsync();
Console.WriteLine("Change Feed Processor started. Press any key to stop.");
Console.ReadKey();

// Stop processor
await changeFeedProcessor.StopAsync();
Console.WriteLine("Change Feed Processor stopped.");
```

### Voorbeeld 2: Advanced Configuration

```csharp
ChangeFeedProcessor changeFeedProcessor = monitoredContainer
    .GetChangeFeedProcessorBuilder<MyItem>(
        processorName: "advancedProcessor",
        onChangesDelegate: HandleChangesAsync)
    .WithInstanceName(Environment.MachineName)  // Unique identifier
    .WithLeaseContainer(leaseContainer)
    
    // ⚙️ Performance tuning
    .WithMaxItems(100)  // Max items per batch (default: unlimited)
    .WithPollInterval(TimeSpan.FromSeconds(5))  // Poll interval (default: 5 sec)
    
    // 🕐 Start options
    .WithStartTime(DateTime.UtcNow.AddDays(-7))  // Start from specific time
    // .FromBeginning()  // Start from eerste change ooit
    // (default: start from nu)
    
    // 🔧 Error handling
    .WithErrorNotification((leaseToken, exception) =>
    {
        Console.WriteLine($"Error on lease {leaseToken}: {exception.Message}");
        return Task.CompletedTask;
    })
    
    .Build();

await changeFeedProcessor.StartAsync();
```

### Voorbeeld 3: Azure Functions Integration

```csharp
// Azure Function triggered by Cosmos DB Change Feed
using Microsoft.Azure.Functions.Worker;
using Microsoft.Extensions.Logging;
using Microsoft.Azure.Cosmos;

public class CosmosDBTriggerFunction
{
    private readonly ILogger _logger;

    public CosmosDBTriggerFunction(ILoggerFactory loggerFactory)
    {
        _logger = loggerFactory.CreateLogger<CosmosDBTriggerFunction>();
    }

    [Function("ProcessChanges")]
    public void Run(
        [CosmosDBTrigger(
            databaseName: "myDatabase",
            containerName: "monitoredContainer",
            Connection = "CosmosDBConnection",  // App setting
            LeaseContainerName = "leases",
            CreateLeaseContainerIfNotExists = true,
            StartFromBeginning = false
        )]
        IReadOnlyList<MyItem> input)
    {
        if (input != null && input.Count > 0)
        {
            _logger.LogInformation($"Processing {input.Count} changes");

            foreach (var item in input)
            {
                _logger.LogInformation($"Change: {item.id} - {item.name}");
                
                // Custom processing
                ProcessItem(item);
            }
        }
    }

    private void ProcessItem(MyItem item)
    {
        // Your business logic here
        // - Send notification
        // - Update materialized view
        // - Sync to another database
        // - Trigger workflow
    }
}

public class MyItem
{
    public string id { get; set; }
    public string name { get; set; }
    public string status { get; set; }
}
```

### Voorbeeld 4: Soft Delete Pattern

```csharp
// Workaround voor delete tracking met TTL

// 1️⃣ Update item to mark as deleted (instead of hard delete)
var item = await container.ReadItemAsync<MyItem>("item-123", new PartitionKey("user-123"));
item.Resource.isDeleted = true;
item.Resource.ttl = 3600; // Expire na 1 uur

await container.ReplaceItemAsync(item.Resource, item.Resource.id, new PartitionKey(item.Resource.partitionKey));

// 2️⃣ Change feed detecteert de update
static async Task HandleChangesAsync(
    ChangeFeedProcessorContext context,
    IReadOnlyCollection<MyItem> changes,
    CancellationToken cancellationToken)
{
    foreach (MyItem item in changes)
    {
        if (item.isDeleted)
        {
            Console.WriteLine($"Item marked for deletion: {item.id}");
            // Handle "delete" event
            await ProcessDeletionAsync(item);
        }
        else
        {
            Console.WriteLine($"Item created/updated: {item.id}");
            await ProcessUpdateAsync(item);
        }
    }
}

// 3️⃣ Item class
public class MyItem
{
    public string id { get; set; }
    public string partitionKey { get; set; }
    public string name { get; set; }
    public bool isDeleted { get; set; } = false;
    public int? ttl { get; set; }  // Time to live (seconds)
}
```

### Voorbeeld 5: Multiple Processors (Different Logic)

```csharp
// Scenario: Twee verschillende processors voor dezelfde container

// Processor 1: Real-time notifications
ChangeFeedProcessor notificationProcessor = monitoredContainer
    .GetChangeFeedProcessorBuilder<MyItem>(
        processorName: "notificationProcessor",  // Unique name!
        onChangesDelegate: async (context, changes, ct) =>
        {
            foreach (var item in changes)
            {
                await SendNotificationAsync(item);
            }
        })
    .WithInstanceName("notification-worker")
    .WithLeaseContainer(leaseContainer)
    .Build();

// Processor 2: Analytics/reporting
ChangeFeedProcessor analyticsProcessor = monitoredContainer
    .GetChangeFeedProcessorBuilder<MyItem>(
        processorName: "analyticsProcessor",  // Different processor name
        onChangesDelegate: async (context, changes, ct) =>
        {
            foreach (var item in changes)
            {
                await UpdateAnalyticsAsync(item);
            }
        })
    .WithInstanceName("analytics-worker")
    .WithLeaseContainer(leaseContainer)
    .WithMaxItems(1000)  // Batch processing
    .WithPollInterval(TimeSpan.FromMinutes(5))  // Less frequent
    .Build();

// Start beide processors
await notificationProcessor.StartAsync();
await analyticsProcessor.StartAsync();

// Beide processors verwerken ALLE changes, onafhankelijk
```

## 🔄 Pull Model - Code Voorbeelden

```csharp
using Microsoft.Azure.Cosmos;

var container = cosmosClient.GetContainer("database", "container");

// ========================================
// Pull Model: FeedIterator
// ========================================

// Get change feed iterator
string continuationToken = null; // Of laatste saved token
FeedIterator<MyItem> iterator = container.GetChangeFeedIterator<MyItem>(
    ChangeFeedStartFrom.Beginning(),  // Of .Now(), .Time(datetime), .ContinuationToken(token)
    ChangeFeedMode.Incremental
);

while (iterator.HasMoreResults)
{
    FeedResponse<MyItem> response = await iterator.ReadNextAsync();
    
    if (response.StatusCode == System.Net.HttpStatusCode.NotModified)
    {
        // Geen nieuwe changes
        Console.WriteLine("No new changes. Waiting...");
        await Task.Delay(TimeSpan.FromSeconds(5));
        continue;
    }

    Console.WriteLine($"Processing {response.Count} changes");
    Console.WriteLine($"RU charge: {response.RequestCharge}");

    foreach (var item in response)
    {
        Console.WriteLine($"Change: {item.id}");
        // Process item
    }

    // Save continuation token voor next poll
    continuationToken = response.ContinuationToken;
    await SaveCheckpointAsync(continuationToken);
}

// Later: Resume met saved token
FeedIterator<MyItem> resumedIterator = container.GetChangeFeedIterator<MyItem>(
    ChangeFeedStartFrom.ContinuationToken(continuationToken),
    ChangeFeedMode.Incremental
);
```

## 📊 Push vs Pull Model Vergelijking

| Aspect | Push Model (Processor) | Pull Model (Iterator) |
|--------|------------------------|------------------------|
| **Automatisch** | ✅ Auto-pushed | ❌ Handmatige polling |
| **Checkpoint management** | ✅ Automatisch | ❌ Handmatig |
| **Load balancing** | ✅ Auto over workers | ❌ Manual scaling |
| **Complexity** | 🟡 Matig | 🟢 Laag |
| **Azure Functions** | ✅ Native trigger | ❌ Niet native |
| **Use case** | Real-time, event-driven | Batch, migration, custom control |

## ⚠️ Belangrijke Limitaties

### 🚫 Deletes Worden Niet Getrackt
```csharp
// ❌ Delete wordt NIET gezien in change feed
await container.DeleteItemAsync<MyItem>("item-123", new PartitionKey("user-123"));

// ✅ Workaround: Soft delete
var item = await container.ReadItemAsync<MyItem>("item-123", new PartitionKey("user-123"));
item.Resource.isDeleted = true;
item.Resource.ttl = 86400; // Delete na 24 uur
await container.ReplaceItemAsync(item.Resource, "item-123", new PartitionKey("user-123"));
// Change feed ziet nu de UPDATE met isDeleted = true
```

### 📦 Ordering Alleen Per Partition
```
✅ Guaranteed: Changes binnen partition key "user-123" zijn in volgorde
❌ NOT Guaranteed: Volgorde tussen "user-123" en "user-456" changes
```

### 🔒 Niet Compatible met Alle APIs
- ✅ **API for NoSQL** - Volledig ondersteund
- ✅ **API for MongoDB** - Ondersteund (MongoDB change streams)
- ✅ **API for Cassandra** - Ondersteund
- ✅ **API for Gremlin** - Ondersteund
- ❌ **API for Table** - **NIET ondersteund**
- ❌ **API for PostgreSQL** - **NIET ondersteund**

## 🏆 Best Practices

### ✅ Do's

| Praktijk | Reden |
|----------|-------|
| **Gebruik push model voor real-time** | Automatisch, schaalbaar |
| **Dedicated lease container** | Voorkomt conflicts met monitored container |
| **Unique processor names** | Per logical processor (niet per instance) |
| **Idempotent processing** | Changes kunnen meerdere keren worden gelevered |
| **Error handling** | Graceful degradation bij failures |
| **Monitor lease container** | Check voor stuck leases |
| **Soft delete pattern** | Track deletes via isDeleted + TTL |

### ❌ Don'ts

| Anti-pattern | Waarom niet? |
|--------------|---------------|
| **Hard deletes zonder soft delete** | Deletes worden niet getrackt |
| **Verwachten global ordering** | Ordering alleen per partition |
| **Lease container delen** | Dedicated container per processor |
| **Lange processing in handler** | Blocks nieuwe batches |
| **Vergeten checkpoints** | Pull model moet zelf state beheren |
| **Throttling negeren** | Monitor RU consumption |

## 📈 Monitoring & Troubleshooting

### Azure Portal Metrics

| Metric | Wat te checken |
|--------|----------------|
| **Change Feed RU Consumption** | Hoeveel RUs gebruikt door change feed reads |
| **Lease Container Size** | Grootte van lease container |
| **Processing Lag** | Vertraging tussen write en processing |

### Common Issues

**Issue: Processing lag**
```
Oorzaak: Handler is te langzaam
Oplossing: 
- Verhoog aantal worker instances (horizontal scaling)
- Optimize handler code
- Batch processing in handler
```

**Issue: Stuck leases**
```
Oorzaak: Worker crashed zonder lease cleanup
Oplossing:
- Implement proper shutdown (StopAsync)
- Monitor lease TTL
- Manual lease cleanup via lease container
```
