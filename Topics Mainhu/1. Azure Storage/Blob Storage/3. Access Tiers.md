# 🌡️ Access Tiers (Toegangslagen)

## 🤔 Wat zijn Access Tiers?

Access Tiers zijn **storage lagen** die je helpen kosten te optimaliseren op basis van hoe vaak je data toegankelijk moet zijn.

**Basis principe:**
```
Vaker toegang nodig = Duurder storage, goedkopere access
Minder toegang = Goedkoper storage, duurdere access
```

---

## 🎨 Vier Access Tiers

### 1️⃣ Hot Tier ⚡

**Gebruik voor:** Frequently accessed of modified data

**Kenmerken:**
- ⚡ Instant access
- 💰💰 Duurste storage cost
- 💰 Goedkoopste transaction cost
- ⚡ Beste performance

**Kosten Breakdown:**
```
Storage: ~$0.0184 per GB/maand
Transactions: ~$0.0004 per 10,000 reads
Data egress: Standaard rates
```

**Use Cases:**
```
✅ Active website images en videos
✅ Frequently read documents
✅ Application data
✅ Real-time analytics data
✅ Data in active use
```

**Retention:** Geen minimum retention period

### 2️⃣ Cool Tier ❄️

**Gebruik voor:** Infrequently accessed data (min 30 dagen)

**Kenmerken:**
- ⚡ Instant access (iets langzamer)
- 💰 Goedkopere storage cost (~50% van Hot)
- 💰💰 Duurdere transaction cost
- ⏰ Minimum 30 dagen storage

**Kosten Breakdown:**
```
Storage: ~$0.01 per GB/maand
Transactions: ~$0.01 per 10,000 reads
Early deletion: Penalty voor <30 dagen
```

**Use Cases:**
```
✅ Short-term backups
✅ Older media content
✅ Data sets voor future processing
✅ Development/test data
✅ Disaster recovery data
```

**Early Deletion Penalty:**
```
Upload blob → Delete na 15 dagen
└── Je betaalt voor 30 dagen!
    ├── 15 dagen actual storage
    └── 15 dagen penalty
```

### 3️⃣ Cold Tier 🧊 (Preview)

**Gebruik voor:** Rarely accessed data (min 90 dagen)

**Kenmerken:**
- ⚡ Instant access (langzamer)
- 💰 Nog goedkopere storage cost
- 💰💰💰 Nog duurdere transaction cost
- ⏰ Minimum 90 dagen storage

**Kosten Breakdown:**
```
Storage: ~$0.004 per GB/maand
Transactions: ~$0.02 per 10,000 reads
Early deletion: Penalty voor <90 dagen
```

**Use Cases:**
```
✅ Long-term backups
✅ Compliance archives (need occasional access)
✅ Historical data
✅ Secondary backup copies
```

### 4️⃣ Archive Tier 📦

**Gebruik voor:** Rarely accessed data (min 180 dagen)

**Kenmerken:**
- 🐌 **OFFLINE** - Vereist rehydration!
- 💰 Goedkoopste storage cost
- 💰💰💰💰 Duurste transaction cost
- ⏰ Minimum 180 dagen storage
- ⏰ Rehydration: 1-15 uur

**Kosten Breakdown:**
```
Storage: ~$0.002 per GB/maand (99% goedkoper!)
Transactions: ~$0.05 per 10,000 reads
Rehydration: ~$0.022 per GB
Early deletion: Penalty voor <180 dagen
```

**Use Cases:**
```
✅ Long-term archival
✅ Compliance data (rarely accessed)
✅ Tape replacement
✅ Historical records
✅ Legal/regulatory archives
```

**⚠️ Belangrijk:**
```
Archive is OFFLINE:
└── Data niet direct toegankelijk
    └── Eerst rehydraten (1-15 uur)
        ├── Copy to online tier, OF
        └── Change tier to online
```

```
└── Cold/Archive tier 🧊
```

**Savings:** ~80% op storage costs!

```
└── Cold tier 🧊
    └── Disaster recovery

└── Archive tier 📦
```

## 🎯 Tier Levels

Access tiers kunnen worden ingesteld op **twee niveaus**:

### 1️⃣ Account Level (Default Tier)

**Wat:** Default tier voor alle nieuwe blobs in het account

```bash
az storage account create \
  --name mystorageaccount \
  --access-tier Hot  # Of Cool

# Update default tier
az storage account update \
  --name mystorageaccount \
  --access-tier Cool
```

**Kenmerken:**
- ✅ Alleen Hot of Cool (niet Archive!)
- ✅ Applies to blobs zonder explicit tier
- ✅ Kan later gewijzigd worden
- ⚠️ Premium accounts: Inherited from SKU

**Voorbeeld:**
```
Account default tier: Cool
├── Blob A (no explicit tier) → Cool ✅
├── Blob B (explicit Hot tier) → Hot ✅
└── Blob C (no explicit tier) → Cool ✅
```

### 2️⃣ Blob Level (Individual Tier)

**Wat:** Specifieke tier per blob

```bash
az storage blob set-tier \
  --account-name mystorageaccount \
  --container-name mycontainer \
  --name myblob.txt \
  --tier Archive
```

**Kenmerken:**
- ✅ Hot, Cool, Cold, of Archive
- ✅ Overrides account default
- ✅ Kan later gewijzigd worden
- ⚠️ Archive alleen voor Block Blobs

**C# Voorbeeld:**
```csharp
BlobClient blobClient = containerClient.GetBlobClient("myblob.txt");

// Set tier tijdens upload
BlobUploadOptions options = new BlobUploadOptions
{
    AccessTier = AccessTier.Cool
};
await blobClient.UploadAsync(stream, options);

// Change tier later
await blobClient.SetAccessTierAsync(AccessTier.Archive);
```

## 🔄 Tier Changes

### Tier Transition Rules

```
Hot ↔ Cool ↔ Cold ↔ Archive
└── Kan in beide richtingen
    ├── Cooling: Naar rechts (cheaper)
    └── Heating: Naar links (instant access)
```

### Cooling (Going Offline)

```
Hot → Cool:   Instant ✅
Cool → Cold:  Instant ✅
Cold → Archive: Instant ✅
Hot → Archive: Direct mogelijk ✅
```

**Kosten:** Minimal transition cost

### Heating (Going Online)

```
Archive → Cold:  Rehydration required 🐌
Archive → Cool:  Rehydration required 🐌
Archive → Hot:   Rehydration required 🐌
Cold → Cool:    Instant ✅
Cool → Hot:     Instant ✅
```

**Rehydration tijd:** 1-15 uur (afhankelijk van priority)

## 🔥 Rehydration (Archive → Online)

### Wat is Rehydration?

**Probleem:** Archive blobs zijn offline  
**Oplossing:** Rehydrate naar online tier

### Twee Methoden

#### 1️⃣ Change Tier (In-place)

```bash
az storage blob set-tier \
  --tier Hot \
  --rehydrate-priority High
```

**Proces:**
```
Archive Blob
└── Set tier to Hot/Cool
    └── Rehydration starts
        └── 1-15 hours later
            └── Blob is Hot/Cool ✅
```

**Characteristics:**
- Same blob URI
- Blob inaccessible tijdens rehydration
- Original blob vervangen

#### 2️⃣ Copy to Online Tier

```bash
az storage blob copy start \
  --source-blob archived-blob.txt \
  --destination-blob active-blob.txt \
  --tier Hot
```

**Proces:**
```
Archive Blob (blijft bestaan)
└── Copy to nieuwe blob
    └── 1-15 hours later
        └── Nieuwe Hot/Cool blob ✅
```

**Characteristics:**
- Nieuwe blob URI
- Original blijft in Archive
- Kan beginnen met lezen zodra copy klaar is

### Rehydration Priority

**Standard Priority:**
```
Cost: Lower
Time: Up to 15 hours
Use: Non-urgent data
```

**High Priority:**
```
Cost: Higher (~10x)
Time: <1 hour (for blobs <10 GB)
Use: Urgent data access
```

```bash
az storage blob set-tier \
  --tier Hot \
  --rehydrate-priority High  # Standard of High
```

**Check status:**
```http
GET https://account.blob.core.windows.net/container/blob

Response Headers:
x-ms-rehydrate-priority: High
x-ms-archive-status: rehydrate-pending-to-hot
```

### Rehydration Beperkingen

```
❌ Cannot read blob during rehydration
❌ Cannot change priority once started
❌ Cannot cancel rehydration
✅ Can check status via x-ms-archive-status header
```

## 📋 Supported Blob Types per Tier

| Blob Type | Hot | Cool | Cold | Archive |
|-----------|-----|------|------|---------|
| **Block Blobs** | ✅ | ✅ | ✅ | ✅ |
| **Append Blobs** | ✅ | ⚠️ Always Hot | ⚠️ Always Hot | ❌ |
| **Page Blobs** | ✅ | ✅ | ✅ | ❌ |

**Append Blobs:**
```
Append blobs considered always "Hot"
└── Cannot set to Cool, Cold, or Archive
    └── Designed for frequent appends
```

## ⚠️ Important Considerations

### 1. Last Modified Time

```
Tier change does NOT update last modified time:

Upload blob: 2024-01-01
└── Last Modified: 2024-01-01

Change tier: 2024-06-01
└── Last Modified: Still 2024-01-01 ⚠️
```

**Impact op Lifecycle Policies:**
```
If policy checks last modified time:
└── Blob might be moved back to Archive
    └── If last modified > threshold
```

### 2. Early Deletion Penalties

**Cool Tier (30 days):**
```
Upload: Day 0
Delete: Day 15
Charge: 30 days of storage (15 days penalty)
```

**Cold Tier (90 days):**
```
Upload: Day 0
Delete: Day 45
Charge: 90 days of storage (45 days penalty)
```

**Archive Tier (180 days):**
```
Upload: Day 0
Delete: Day 100
Charge: 180 days of storage (80 days penalty)
```

**Advies:** Kies tier met retention < required time!

### 3. Redundancy Restrictions

```
Archive tier restrictions:
❌ ZRS redundancy not supported
❌ GZRS redundancy not supported
✅ LRS supported
✅ GRS supported
✅ RA-GRS supported
```

### 4. Premium Storage

```
Premium Block Blob Storage:
└── Only Premium tier available
    ❌ No Hot/Cool/Archive
    └── Inherits from account SKU
```

## 💰 Cost Calculation Examples

### Example 1: 100 GB Hot → Cool

**Hot tier (1 maand):**
```
Storage: 100 GB × $0.0184 = $1.84
Transactions: 10,000 reads × $0.0004 = $0.004
Total: ~$1.84/maand
```

**Cool tier (1 maand):**
```
Storage: 100 GB × $0.01 = $1.00
Transactions: 10,000 reads × $0.01 = $0.10
Total: ~$1.10/maand
```

**Savings:** ~40% if reads < 100,000/maand

### Example 2: 1 TB Archive

**Hot tier (1 jaar):**
```
Storage: 1000 GB × $0.0184 × 12 = $220.80
```

**Archive tier (1 jaar):**
```
Storage: 1000 GB × $0.002 × 12 = $24.00
Rehydration (2x per jaar): 1000 GB × $0.022 × 2 = $44.00
Total: ~$68.00/jaar
```

**Savings:** ~69% zelfs met 2 rehydrations!

## 🔄 CLI Commands

```bash

az storage account create \
  --name mystorageaccount \
  --access-tier Hot

# Update existing
az storage account update \
  --name mystorageaccount \
```

```bash
# Set tier voor individuele blob
az storage blob set-tier \
  --account-name mystorageaccount \
  --container-name mycontainer \
  --name myblob.txt \
  --tier Archive \
  --rehydrate-priority Standard

# Batch operation (alle blobs in container)
az storage blob set-tier \
  --account-name mystorageaccount \
  --container-name mycontainer \
  --tier Cool \
  --pattern "*.log"
```

```bash
az storage blob show \
  --account-name mystorageaccount \
  --container-name mycontainer \
  --name myblob.txt \
  --query "properties.tier"
```

## 💻 C# Examples

### Upload met Tier

```csharp
BlobClient blobClient = containerClient.GetBlobClient("myblob.txt");

// Upload to specific tier
BlobUploadOptions options = new BlobUploadOptions
{
    AccessTier = AccessTier.Cool
};

await blobClient.UploadAsync(fileStream, options);
```

### Change Tier

```csharp
// Move to Archive
await blobClient.SetAccessTierAsync(AccessTier.Archive);

// Rehydrate to Hot with high priority
await blobClient.SetAccessTierAsync(
    AccessTier.Hot,
    rehydratePriority: RehydratePriority.High
);
```

### Check Rehydration Status

```csharp
BlobProperties properties = await blobClient.GetPropertiesAsync();

if (properties.Value.ArchiveStatus == ArchiveStatus.RehydratePendingToHot)
{
    Console.WriteLine("Rehydration in progress...");
    Console.WriteLine($"Priority: {properties.Value.RehydratePriority}");
}
```

### Copy Archive Blob

```csharp
BlobClient sourceBlob = containerClient.GetBlobClient("archived.txt");
BlobClient targetBlob = containerClient.GetBlobClient("rehydrated.txt");

// Start copy met target tier
var operation = await targetBlob.StartCopyFromUriAsync(
    sourceBlob.Uri,
    new BlobCopyFromUriOptions
    {
        AccessTier = AccessTier.Hot,
        RehydratePriority = RehydratePriority.High
    }
);

// Wait for completion
await operation.WaitForCompletionAsync();
```

## ✅ Best Practices

### 1. Tier Selection

```
Choose tier based on access pattern:

Hot:
└── Access > 1x per day
    └── Active data

Cool:
└── Access 1-2x per month
    └── Will be stored > 30 days

Cold:
└── Access 1-2x per quarter
    └── Will be stored > 90 days

Archive:
└── Access < 1x per year
    └── Will be stored > 180 days
```

### 2. Lifecycle Policies

```
Automate tier transitions:

Day 0:     Upload → Hot
Day 30:    Auto → Cool
Day 180:   Auto → Cold
Day 365:   Auto → Archive

(Zie Lifecycle Management document)
```

### 3. Rehydration Strategy

```
Plan rehydrations:

Predictable access:
└── Use scheduled copy
    └── Rehydrate during off-hours

Urgent access:
└── Use High priority
    └── Pay premium for speed

Partial access:
└── Copy specific blobs
    └── Keep others in Archive
```

### 4. Cost Monitoring

```
Track costs per tier:

Monitor:
├── Storage costs per tier
├── Transaction costs
├── Early deletion penalties
└── Rehydration costs

Optimize:
└── Adjust tier strategy based on actual usage
```

## 🎓 Samenvatting

### Key Takeaways

1. **4 Tiers:** Hot (active), Cool (30d+), Cold (90d+), Archive (180d+, offline)
2. **Trade-off:** Storage cost ↔ Access cost
3. **Levels:** Account default + Individual blob tier
4. **Archive:** Offline, requires rehydration (1-15 hours)
5. **Penalties:** Early deletion voor Cool/Cold/Archive
6. **Transitions:** Easy between tiers, Archive needs rehydration
7. **Savings:** Up to 99% op storage costs met Archive

### Decision Guide

```
Access frequency:
├── Multiple times per day → Hot
├── Few times per month → Cool
├── Few times per quarter → Cold
└── Few times per year → Archive

Data criticality:
├── Critical, need instant access → Hot/Cool
├── Important, can wait hours → Cold
└── Archival, can wait 15 hours → Archive

Cost sensitivity:
├── Performance > Cost → Hot
├── Balanced → Cool
├── Cost > Convenience → Cold
└── Minimal cost → Archive
```
