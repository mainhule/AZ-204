# 🔐 Security & Authentication

## 🤔 Authentication Methods Overzicht

Azure Blob Storage ondersteunt **vier authentication methods**:

| Method | Type | Use Case | Security |
|--------|------|----------|----------|
| **Shared Key** | Account Key | Legacy, simple access | ⚠️ Full access |
| **Entra ID** | Identity-based | Enterprise, RBAC | ✅ Best |
| **SAS Token** | Delegated access | Limited, temporary | ✅ Good |
| **Anonymous** | Public access | Public content | ⚠️ No auth |

---

## 1️⃣ Shared Key (Storage Account Key)

### Wat is het?

**Secret password** dat **volledige toegang** geeft tot je storage account.

**Kenmerken:**
- 🔑 Two keys (key1 en key2)
- ✅ Full access to all data
- ⚠️ Cannot be scoped (all or nothing)
- ♻️ Can be regenerated

### CLI Example

```bash
# Get account keys
az storage account keys list \
  --account-name mystorageaccount \
  --query '[0].value' \
  --output tsv

# Use key for authentication
az storage blob upload \
  --account-name mystorageaccount \
  --account-key "your-key-here" \
  --container-name mycontainer \
  --name myblob.txt \
  --file ./local-file.txt
```

### C# Example
    
```csharp
string accountName = "mystorageaccount";
string accountKey = "your-key-here";

var credential = new StorageSharedKeyCredential(accountName, accountKey);
var blobServiceClient = new BlobServiceClient(
    new Uri($"https://{accountName}.blob.core.windows.net"),
    credential
);
```

### HTTP Header

```http
Authorization: SharedKey mystorageaccount:[signature]
```

### ⚠️ Waarschuwingen

```
❌ Volledige toegang (cannot restrict)
❌ Lastig te roteren zonder downtime
❌ Key exposed = complete compromise
⚠️ Use alleen voor legacy/simple scenarios
✅ Prefer Entra ID of SAS tokens
```

### Key Rotation

```bash
# Rotation zonder downtime:
1. Apps gebruiken key1
2. Regenereer key2
3. Update apps naar key2
4. Wait for propagation
5. Regenereer key1 (nu veilig)
```

## 2️⃣ Microsoft Entra ID (Azure AD) ⭐ AANBEVOLEN

### Wat is het?

**Identity-based authentication** met Role-Based Access Control (RBAC).

**Voordelen:**
```
✅ No credentials in code
✅ Fine-grained permissions (RBAC)
✅ Audit trail
✅ MFA support
✅ Managed identities
```

### Delegation Scope

```
Resource ID: https://storage.azure.com/
Scope: user_impersonation
```

### RBAC Roles

| Role | Permissions | Use Case |
|------|-------------|----------|
| **Storage Blob Data Owner** | Full access | Admins |
| **Storage Blob Data Contributor** | Read, write, delete | Applications |
| **Storage Blob Data Reader** | Read only | Reporting, analytics |
| **Storage Blob Delegator** | Get user delegation key (for SAS) | SAS generation |

### Detailed Permissions

```
Microsoft.Storage/storageAccounts/blobServices/
├── read                    (List containers)
├── write                   (Create container)
├── delete                  (Delete container)
├── containers/
│   ├── read               (List blobs)
│   ├── write              (Create blob)
│   ├── delete             (Delete blob)
│   └── blobs/
│       ├── read           (Read blob)
│       ├── write          (Write blob)
│       ├── delete         (Delete blob)
│       └── filter/action  (Find blobs by tags)
```

### CLI Example

```bash
# Assign role
az role assignment create \
  --role "Storage Blob Data Contributor" \
  --assignee user@contoso.com \
  --scope /subscriptions/{sub-id}/resourceGroups/{rg}/providers/Microsoft.Storage/storageAccounts/{account}

# Use with Azure CLI (uses az login credentials)
az storage blob upload \
  --account-name mystorageaccount \
  --auth-mode login \
  --container-name mycontainer \
  --name myblob.txt \
  --file ./local-file.txt
```

### C# Example (DefaultAzureCredential)

```csharp
// Uses: Managed Identity, Azure CLI, Visual Studio, etc.
var credential = new DefaultAzureCredential();

var blobServiceClient = new BlobServiceClient(
    new Uri("https://mystorageaccount.blob.core.windows.net"),
    credential
);

// Works automatically in:
// - Azure (Managed Identity)
// - Local dev (az login)
// - Visual Studio (signed-in account)
```

### C# Example (Service Principal)

```csharp
var credential = new ClientSecretCredential(
    tenantId: "your-tenant-id",
    clientId: "your-client-id",
    clientSecret: "your-client-secret"
);

var blobServiceClient = new BlobServiceClient(
    new Uri("https://mystorageaccount.blob.core.windows.net"),
    credential
);
```

### Managed Identity (Best for Azure resources)

```bash
# Enable managed identity on VM/App Service/Function
az vm identity assign --name MyVM

# Assign storage role
az role assignment create \
  --role "Storage Blob Data Contributor" \
  --assignee-object-id <managed-identity-object-id> \
  --scope <storage-account-resource-id>
```

```csharp
// In code (automatic!)
var credential = new DefaultAzureCredential();
// Automatically uses managed identity in Azure
```

## 3️⃣ Shared Access Signature (SAS) Tokens

### Wat is een SAS Token?

**Tijdelijke, limited-access** URL voor specifieke resources.

**Types:**
- **User Delegation SAS** (Entra ID-based) ✅ Best
- **Service SAS** (Account Key-based)
- **Account SAS** (Account Key-based, broader scope)

### User Delegation SAS (Aanbevolen)

**Voordelen:**
```
✅ Based on Entra ID (no account key exposure)
✅ Time-limited
✅ Permission-limited
✅ Resource-scoped
```

```bash
# Generate User Delegation SAS
az storage blob generate-sas \
  --account-name mystorageaccount \
  --container-name mycontainer \
  --name myblob.txt \
  --permissions r \
  --expiry 2024-12-31T23:59:59Z \
  --auth-mode login \
  --as-user
```

### Service SAS

```bash
# Generate Service SAS (uses account key)
az storage blob generate-sas \
  --account-name mystorageaccount \
  --account-key "your-key" \
  --container-name mycontainer \
  --name myblob.txt \
  --permissions rwd \
  --expiry 2024-12-31T23:59:59Z \
  --https-only
```

### SAS Token Format

```
https://mystorageaccount.blob.core.windows.net/container/blob?
sv=2021-06-08&           # Storage version
ss=b&                    # Service (b=blob)
srt=sco&                 # Resource types
sp=rwdlac&               # Permissions
se=2024-12-31T23:59:59Z& # Expiry
st=2024-01-01T00:00:00Z& # Start time
spr=https&               # Protocol
sig=<signature>          # Signature
```

### Permissions

| Permission | Description | Actions |
|-----------|-------------|---------|
| **r** | Read | Download blob, read properties |
| **w** | Write | Upload, update blob |
| **d** | Delete | Delete blob |
| **l** | List | List blobs in container |
| **a** | Add | Append to append blob |
| **c** | Create | Create blob |

### C# Generate SAS

```csharp
BlobSasBuilder sasBuilder = new BlobSasBuilder
{
    BlobContainerName = "mycontainer",
    BlobName = "myblob.txt",
    Resource = "b", // b = blob
    StartsOn = DateTimeOffset.UtcNow,
    ExpiresOn = DateTimeOffset.UtcNow.AddHours(1)
};

sasBuilder.SetPermissions(BlobSasPermissions.Read);

// Generate SAS token
string sasToken = sasBuilder.ToSasQueryParameters(
    new StorageSharedKeyCredential(accountName, accountKey)
).ToString();

// Full URL
string sasUrl = $"https://{accountName}.blob.core.windows.net/{containerName}/{blobName}?{sasToken}";
```

### Use SAS Token

```csharp
// Client with SAS
var blobClient = new BlobClient(new Uri(sasUrl));

// No credentials needed - SAS is in URL
await blobClient.DownloadToAsync("local-file.txt");
```

## 4️⃣ Anonymous Public Access

### Container-level Public Access

```bash
az storage container create \
  --name mycontainer \
  --public-access blob  # Or: container, off
```

**Access Levels:**

| Level | Description | Access |
|-------|-------------|--------|
| **Off** | No public access | Auth required |
| **Blob** | Public read for blobs only | Direct blob URLs work |
| **Container** | Public read for container + blobs | List + read blobs |

### ⚠️ Security Considerations

```
Anonymous access is disabled by default on storage account level!

Enable at account level:
az storage account update \
  --name mystorageaccount \
  --allow-blob-public-access true
```

**Use Cases:**
```
✅ Public website assets (CDN)
✅ Public downloads
✅ Open datasets

❌ Sensitive data
❌ User uploads
❌ Enterprise data
```

## 🔒 Encryption

### Encryption at Rest (Automatisch)

**Microsoft-Managed Keys (default):**
```
✅ Automatic encryption
✅ 256-bit AES
✅ No configuration needed
✅ Free
```

```bash
# Default (Microsoft keys)
az storage account create \
  --encryption-key-source Microsoft.Storage
```

### Customer-Managed Keys (CMK)

**Voor extra controle:**

```bash
# Setup Key Vault
az keyvault create --name myvault

# Create key
az keyvault key create --vault-name myvault --name mykey

# Configure storage account
az storage account create \
  --encryption-key-source Microsoft.Keyvault \
  --encryption-key-name mykey \
  --encryption-key-vault https://myvault.vault.azure.net
```

**Kenmerken:**
```
✅ You control key rotation
✅ Stored in Azure Key Vault
✅ Revoke access instantly
💰 Additional cost (Key Vault)
```

### Infrastructure Encryption

**Dubbele encryptie:**

```bash
az storage account create \
  --require-infrastructure-encryption true
```

**Layers:**
```
Layer 1: Service-level encryption (256-bit AES)
Layer 2: Infrastructure encryption (separate key)
```

### Client-Side Encryption

**Encrypt before upload:**

```csharp
// Your encryption key
IKeyEncryptionKey key = ...;

var encryptionOptions = new ClientSideEncryptionOptions(ClientSideEncryptionVersion.V2_0)
{
    KeyEncryptionKey = key,
    KeyWrapAlgorithm = "RSA-OAEP"
};

var options = new SpecializedBlobClientOptions 
{ 
    ClientSideEncryption = encryptionOptions 
};

var blobClient = new BlobServiceClient(uri, credential, options);

// Data encrypted before leaving client!
```

## 🌐 Network Security

### Firewall Rules

```bash
# Deny all by default
az storage account update \
  --name mystorageaccount \
  --default-action Deny

# Allow specific IP
az storage account network-rule add \
  --account-name mystorageaccount \
  --ip-address 203.0.113.0/24

# Allow specific VNet subnet
az storage account network-rule add \
  --account-name mystorageaccount \
  --vnet-name myvnet \
  --subnet mysubnet
```

### Private Endpoints

```bash
# Create private endpoint
az network private-endpoint create \
  --name myendpoint \
  --resource-group MyResourceGroup \
  --vnet-name myvnet \
  --subnet mysubnet \
  --private-connection-resource-id <storage-account-id> \
  --group-id blob \
  --connection-name myconnection
```

**Voordelen:**
```
✅ Private IP in VNet
✅ No public internet exposure
✅ Secure access via private network
```

### Require HTTPS

```bash
az storage account create \
  --https-only true \
  --min-tls-version TLS1_2
```

## ✅ Best Practices

### 1. Authentication Hierarchy

```
Best → Worst:

1. Entra ID + Managed Identity
   └── Voor Azure resources (VM, App Service, Function)

2. Entra ID + Service Principal
   └── Voor apps outside Azure

3. User Delegation SAS
   └── Voor temporary, limited access

4. Service SAS
   └── Als Entra ID niet mogelijk

5. Shared Key
   └── Alleen voor legacy/simple scenarios

6. Anonymous
   └── Alleen voor public content
```

### 2. Security Checklist

```
✅ Enable HTTPS only
✅ Use TLS 1.2 minimum
✅ Enable firewall (deny all, allow specific)
✅ Use Entra ID authentication
✅ Regular access reviews
✅ Enable logging and monitoring
✅ Use private endpoints (if needed)
✅ Rotate keys regularly
✅ Use SAS with short expiry
✅ Disable public blob access (unless needed)
```

### 3. Key Management

```
Shared Keys:
├── Rotate quarterly
├── Use key2 for rotation (no downtime)
├── Never commit to source control
└── Store in Azure Key Vault

SAS Tokens:
├── Short expiry (hours/days, not months)
├── Minimal permissions needed
├── IP restrictions when possible
└── Revoke via Stored Access Policy
```

### 4. Monitoring

```
Enable diagnostics:
├── Azure Monitor logs
├── Storage Analytics
├── Failed auth attempts
└── Anonymous access patterns
```

## 🎓 Samenvatting

### Key Takeaways

1. **Entra ID** = Best authentication method (RBAC, audit, MFA)
2. **SAS Tokens** = Temporary, limited access (use User Delegation SAS)
3. **Shared Key** = Full access, use sparingly
4. **Encryption** = Automatic at rest, optionally at transit/client
5. **Network security** = Firewall, private endpoints, HTTPS-only
6. **Regular rotation** = Keys and SAS tokens

### Decision Guide

```
Choose authentication based on:

Azure resource (VM, App Service):
└── Managed Identity ⭐

App outside Azure:
└── Service Principal (Entra ID)

Temporary external access:
└── User Delegation SAS

Simple internal tool:
└── Shared Key (with caution)

Public content:
└── Anonymous (container-level)
```
