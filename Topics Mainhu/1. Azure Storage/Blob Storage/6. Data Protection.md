# 🛡️ Data Protection

## 🤔 Overview

Azure Blob Storage biedt meerdere data protection features:

| Feature | Purpose | Recovery |
|---------|---------|----------|
| **Versioning** | Auto save versions | Point-in-time |
| **Snapshots** | Manual backups | Point-in-time |
| **Soft Delete** | Trash bin | Time-limited |
| **Leasing** | Concurrent control | Prevention |

---

## 1️⃣ Blob Versioning

### Wat is het?

**Automatisch** bewaren van vorige versies bij elke wijziging.

### Kenmerken

```
✅ Automatic version creation
✅ Each version has unique ID
✅ Previous versions are read-only
✅ Works with all access tiers
✅ Can be deleted via lifecycle policy
```

### Enable Versioning

```bash
az storage account blob-service-properties update \
  --account-name mystorageaccount \
  --enable-versioning true
```

### How it Works

```
Upload blob v1:
└── Current version: v1 (version ID: abc123)

Update blob:
├── Previous version: v1 (read-only, version ID: abc123)
└── Current version: v2 (version ID: def456)

Update again:
├── Previous version: v1 (read-only)
├── Previous version: v2 (read-only)
└── Current version: v3 (version ID: ghi789)
```

### C# Example

```csharp
// Upload creates first version
await blobClient.UploadAsync(stream1);
// Version ID: abc123

// Update creates new version
await blobClient.UploadAsync(stream2, overwrite: true);
// Version ID: def456 (current)
// Version ID: abc123 (previous, read-only)

// List versions
await foreach (BlobItem item in containerClient.GetBlobsAsync(
    BlobTraits.None, 
    BlobStates.Version))
{
    Console.WriteLine($"Version: {item.VersionId}");
}

// Access specific version
var versionedBlobClient = blobClient.WithVersion("abc123");
await versionedBlobClient.DownloadToAsync("old-version.txt");
```

### URI Format

```
Current version:
https://account.blob.core.windows.net/container/blob

Specific version:
https://account.blob.core.windows.net/container/blob?versionid=abc123
```

### Soft Delete Interaction

```
Delete blob with versioning:
├── Current version → Becomes previous version
└── No current version exists

With soft delete:
├── Previous versions preserved
└── Can undelete to restore current version
```

## 2️⃣ Snapshots

### Wat is het?

**Manuele** read-only copy van een blob op een specifiek moment.

### Kenmerken

```
✅ Manual creation
✅ Read-only once created
✅ Share base blob's content
✅ DateTime in URI
❌ Not in Archive tier
✅ Must be deleted explicitly
```

### Create Snapshot

```bash
az storage blob snapshot \
  --account-name mystorageaccount \
  --container-name mycontainer \
  --name myblob.txt
```

### C# Example

```csharp
// Create snapshot
BlobSnapshotInfo snapshotInfo = await blobClient.CreateSnapshotAsync();
string snapshotTime = snapshotInfo.Snapshot;

// Access snapshot
var snapshotClient = blobClient.WithSnapshot(snapshotTime);
await snapshotClient.DownloadToAsync("snapshot.txt");

// List snapshots
var blobs = containerClient.GetBlobsAsync(BlobTraits.None, BlobStates.Snapshots);
await foreach (BlobItem item in blobs)
{
    if (item.Snapshot != null)
    {
        Console.WriteLine($"Snapshot: {item.Snapshot}");
    }
}
```

### URI Format

```
Base blob:
https://account.blob.core.windows.net/container/blob

Snapshot:
https://account.blob.core.windows.net/container/blob?snapshot=2024-01-15T10:30:00.0000000Z
```

### Delete Behavior

```bash
# Delete base blob (fails if snapshots exist)
az storage blob delete --name myblob.txt
# Error: Blob has snapshots

# Delete blob + snapshots
az storage blob delete \
  --name myblob.txt \
  --delete-snapshots include
```

```csharp
// Delete with snapshots
await blobClient.DeleteIfExistsAsync(
    DeleteSnapshotsOption.IncludeSnapshots
);
```

## 3️⃣ Versioning vs Snapshots

| Feature | Versioning | Snapshots |
|---------|-----------|-----------|
| **Creation** | Automatic | Manual |
| **URI** | Version ID | DateTime |
| **Immutability** | Previous = read-only | Always read-only |
| **Tiers** | All | Not Archive |
| **Deletion** | Via policy or explicit | Explicit or with base |
| **Use Case** | Automatic protection | Point-in-time backups |
| **Soft Delete** | Previous version created | Soft-deleted with base |

### Wanneer welke?

```
Versioning:
├── Automatic protection
├── Frequent changes
├── Need full history
└── Easier management

Snapshots:
├── Manual control
├── Before risky operations
├── Point-in-time backups
└── Specific moments
```

## 4️⃣ Soft Delete

### Wat is het?

**Trash bin** voor blobs - verwijderde items blijven tijdelijk herstellen.

### Kenmerken

```
✅ Retention period: 1-365 days
✅ Applies to blobs, snapshots, versions
✅ Undelete within retention period
✅ Auto-deletes after retention
```

### Enable Soft Delete

```bash
# For blobs
az storage account blob-service-properties update \
  --account-name mystorageaccount \
  --enable-delete-retention true \
  --delete-retention-days 7

# For containers
az storage account blob-service-properties update \
  --account-name mystorageaccount \
  --enable-container-delete-retention true \
  --container-delete-retention-days 7
```

### How it Works

```
Delete blob:
├── Blob marked as "soft deleted"
├── Not visible in normal listing
├── Retained for X days
└── Can be undeleted

After retention period:
└── Permanently deleted
```

### C# Example

```csharp
// Delete (soft delete)
await blobClient.DeleteAsync();

// List including soft-deleted
await foreach (BlobItem item in containerClient.GetBlobsAsync(
    BlobTraits.None,
    BlobStates.Deleted))
{
    if (item.IsDeleted)
    {
        Console.WriteLine($"Soft deleted: {item.Name}");
        Console.WriteLine($"Deleted on: {item.Properties.DeletedOn}");
        Console.WriteLine($"Remaining: {item.Properties.RemainingRetentionDays} days");
    }
}

// Undelete
await blobClient.UndeleteAsync();
```

### Soft Delete with Versioning

```
Delete blob with both enabled:
├── Current version → Previous version
├── No current version
└── Can undelete to restore current

Versioning + Soft Delete = Maximum protection!
```

## 5️⃣ Blob Leasing

### Wat is het?

**Lock** op een blob voor exclusive write access.

### Kenmerken

```
✅ Exclusive write lock
✅ Lease duration: 15-60 seconds or infinite
✅ Requires lease ID for modifications
✅ Prevents concurrent modifications
```

### Use Cases

```
✅ Distributed lock mechanism
✅ Prevent concurrent updates
✅ Coordination between processes
✅ Ensure atomic operations
```

### CLI Example

```bash
# Acquire lease (60 seconds)
LEASE_ID=$(az storage blob lease acquire \
  --blob-name myblob.txt \
  --container-name mycontainer \
  --lease-duration 60 \
  --output tsv)

# Use lease for operations
az storage blob upload \
  --name myblob.txt \
  --container-name mycontainer \
  --file new-content.txt \
  --lease-id $LEASE_ID

# Release lease
az storage blob lease release \
  --blob-name myblob.txt \
  --container-name mycontainer \
  --lease-id $LEASE_ID
```

### C# Example

```csharp
// Acquire lease
string proposedLeaseId = Guid.NewGuid().ToString();
var leaseClient = blobClient.GetBlobLeaseClient(proposedLeaseId);
BlobLease lease = await leaseClient.AcquireAsync(TimeSpan.FromSeconds(15));

// Use lease for operations
var uploadOptions = new BlobUploadOptions
{
    Conditions = new BlobRequestConditions 
    { 
        LeaseId = lease.LeaseId 
    }
};

await blobClient.UploadAsync(stream, uploadOptions);

// Renew lease (before expiry)
await leaseClient.RenewAsync();

// Release lease
await leaseClient.ReleaseAsync();

// Break lease (force end)
await leaseClient.BreakAsync();
```

### Lease Operations

```
Acquire: Get new lease
Renew: Extend existing lease
Change: Change lease ID
Release: End lease gracefully
Break: Force end lease (for stuck leases)
```

### Error Handling

```
Operation without lease:
└── 412 Precondition Failed

With wrong lease ID:
└── 412 Precondition Failed

Lease expired:
└── 412 Precondition Failed
└── Must acquire new lease
```

## ✅ Best Practices

### 1. Enable Multiple Layers

```
Maximum protection:
├── Versioning: ON (automatic history)
├── Soft Delete: ON (7-30 days)
└── Snapshots: Manual (before major changes)
```

### 2. Retention Periods

```
Soft Delete:
├── Development: 7 days
├── Production: 14-30 days
└── Compliance: Longer periods

Balance:
├── Longer = Better protection
└── Longer = Higher costs
```

### 3. Lifecycle Policies

```
Delete old versions:
├── Keep last 3 versions
├── Delete versions > 90 days old
└── Delete snapshots > 30 days old

Saves costs while maintaining protection!
```

### 4. Leasing Strategy

```
Use leasing for:
├── Critical updates
├── Distributed systems
└── Atomic operations

Lease duration:
├── Short tasks: 15-60 seconds
├── Long tasks: Infinite (with renew logic)
└── Always release or break when done
```

### 5. Monitoring

```
Track:
├── Soft delete usage (Azure Monitor)
├── Version count per blob
├── Storage costs per protection feature
└── Undelete operations
```

## 💰 Cost Implications

### Versioning

```
Cost = Storage for all versions

Example:
Base blob: 1 GB
10 versions: 10 GB total storage cost

Mitigation:
└── Lifecycle policy to delete old versions
```

### Snapshots

```
Cost = Storage for snapshot data
└── Only changed blocks are charged
    (incremental snapshot)

Example:
Base blob: 1 GB
Snapshot with 100 MB changes: +100 MB cost
```

### Soft Delete

```
Cost = Storage during retention period

Example:
Delete 100 GB
Retention: 30 days
Cost: 100 GB × 30 days storage
```

### Leasing

```
Cost = Free! ✅
└── No additional storage or transaction costs
```

## 🎓 Samenvatting

### Key Takeaways

1. **Versioning** = Automatic protection, alle wijzigingen bewaard
2. **Snapshots** = Manual point-in-time backups
3. **Soft Delete** = Trash bin met retention period
4. **Leasing** = Exclusive write lock voor coordination
5. **Combine features** voor maximum protection
6. **Lifecycle policies** om costs te beheren

### Recommended Setup

```
Production Critical Data:
├── Versioning: ON
├── Soft Delete: 30 days
├── Lifecycle: Delete old versions after 90 days
└── Manual snapshots: Before major changes

Development/Test:
├── Versioning: OFF (save costs)
├── Soft Delete: 7 days
└── Snapshots: As needed

Archival Data:
├── Versioning: OFF
├── Soft Delete: 30 days (compliance)
└── Archive tier after retention
```
