# 🏦 Storage Accounts

## 🤔 Wat is een Storage Account?

Een **Storage Account** is de top-level container die een unieke namespace biedt voor je Azure Storage data. Elke object die je opslaat heeft een adres dat je unieke account naam bevat.

**Endpoint formaat:**
```
https://<storage-account-name>.blob.core.windows.net
```

## 🎨 Storage Account Types (Kind)

### 1️⃣ StorageV2 (General-purpose v2) ⭐ AANBEVOLEN

**Gebruik:** Standaard keuze voor de meeste scenarios

**Ondersteunt:**
- ✅ Blobs (alle types)
- ✅ Files
- ✅ Queues
- ✅ Tables
- ✅ Alle access tiers (Hot, Cool, Cold, Archive)
- ✅ Alle redundancy opties

**Wanneer gebruiken:**
```
✅ Nieuwe projecten
✅ Productie workloads
✅ Need alle features
✅ Cost optimization met tiering
```

### 2️⃣ Storage (General-purpose v1) ⚠️ LEGACY

**Gebruik:** Legacy applications

**Kenmerken:**
- ⚠️ Oudere versie
- ❌ Geen access tier support
- ❌ Hogere transaction costs
- ⚠️ Limited features

**Wanneer gebruiken:**
```
⚠️ Bestaande apps die niet kunnen upgraden
⚠️ Classic deployment model
⚠️ Transaction-heavy apps (soms goedkoper)
```

**Advies:** Upgrade naar StorageV2!

### 3️⃣ BlobStorage ⚠️ LEGACY

**Gebruik:** Blob-only scenarios (oude versie)

**Kenmerken:**
- ✅ Alleen blobs
- ❌ Geen Files, Queues, Tables
- ⚠️ Verouderd

**Wanneer gebruiken:**
```
⚠️ Legacy blob-only apps
✅ Upgrade naar StorageV2 aanbevolen!
```

### 4️⃣ BlockBlobStorage 💎 PREMIUM

**Gebruik:** High-performance blob scenarios

**Kenmerken:**
- ⚡ SSD storage
- ⚡ Zeer lage latency
- 💰 Duurder
- ✅ Block en Append blobs
- ❌ Geen Page blobs
- ❌ Geen Cool/Archive tiers (alleen Premium)

**Wanneer gebruiken:**
```
✅ High transaction rates
✅ Low latency requirements
✅ Small objects (<256 KB)
✅ Real-time analytics
✅ Video streaming
```

**Performance:**
```
BlockBlobStorage vs Standard:
├── Latency: 10x sneller
├── IOPS: 100,000+ vs 20,000
└── Cost: 3-4x duurder
```

### 5️⃣ FileStorage 💎 PREMIUM

**Gebruik:** High-performance file shares

**Kenmerken:**
- ⚡ Premium SSD
- ✅ Alleen Azure Files
- ⚡ High IOPS
- 💰 Duurder

**Wanneer gebruiken:**
```
✅ Enterprise file shares
✅ High IOPS requirements
✅ SQL Server storage
✅ Mission-critical apps
```

```

**Kenmerken:**
- ⚡ SSD storage
- 💰💰💰 Duurder
- ⚡ High performance

**Use Cases:**
```
✅ Low latency (<10ms)
✅ High transaction rates

```

```

├── Large files (>1 MB)
├── Moderate transaction rate
├── Cost is primary concern

## 🔄 Redundancy Options

### LRS (Locally Redundant Storage) 🏷️

**Wat:** 3 kopieën in één datacenter

**Durability:** 99.999999999% (11 nines)

**Use Cases:**
```
✅ Development/testing
✅ Easily reconstructed data
✅ Lowest cost
✅ Data governance restrictions
```

**Kosten:** Goedkoopst  
**Risk:** ❌ Datacenter failure = data loss

**Visual:**
```
┌─────────────────────┐
│   Datacenter West   │
│  ┌─────┐  ┌─────┐  │
│  │Copy1│  │Copy2│  │
│  └─────┘  └─────┘  │
│     ┌─────┐        │
│     │Copy3│        │
│     └─────┘        │
└─────────────────────┘
```

### ZRS (Zone Redundant Storage)

**Wat:** 3 kopieën across 3 availability zones

**Durability:** 99.9999999999% (12 nines)

**Use Cases:**
```
✅ High availability
✅ Regional replication
✅ Azure Files workloads
✅ Production workloads
```

**Kosten:** Moderate  
**Risk:** ✅ Beschermd tegen zone failure

**Visual:**
```
┌─────────────────────────────────┐
│         Region West             │
│  ┌──────┐  ┌──────┐  ┌──────┐  │
│  │Zone 1│  │Zone 2│  │Zone 3│  │
│  │Copy1 │  │Copy2 │  │Copy3 │  │
│  └──────┘  └──────┘  └──────┘  │
└─────────────────────────────────┘
```

**Write Behavior:**
```
Write confirmed when:
└── ALL zones received data
    ├── Zone 1: ✅
    ├── Zone 2: ✅
    └── Zone 3: ✅
```

### GRS (Geo-Redundant Storage)

**Wat:** LRS in primary + LRS in secondary region (async)

**Durability:** 99.99999999999999% (16 nines)

**Use Cases:**
```
✅ Disaster recovery
✅ Business continuity
✅ Regional outage protection
✅ Compliance requirements
```

**Kosten:** Duurder  
**Risk:** ✅ Beschermd tegen regional disaster

**Visual:**
```
┌─────────────────┐       ┌─────────────────┐
│  Primary Region │ Async │ Secondary Region│
│   West Europe   ├──────>│   North Europe  │
│                 │       │                 │
│  ┌─────┐ ┌─────┐│       │ ┌─────┐ ┌─────┐│
│  │Copy1│ │Copy2││       │ │Copy1│ │Copy2││
│  └─────┘ └─────┘│       │ └─────┘ └─────┘│
│     ┌─────┐     │       │    ┌─────┐     │
│     │Copy3│     │       │    │Copy3│     │
│     └─────┘     │       │    └─────┘     │
└─────────────────┘       └─────────────────┘
```

**Replication Delay:**
```
Primary write → Secondary replication
             └── ~15 minutes (async)
             └── No SLA on sync time!
```

### GZRS (Geo-Zone Redundant Storage) 🦺

**Wat:** ZRS in primary + LRS in secondary region

**Durability:** 99.99999999999999% (16 nines)

**Use Cases:**
```
✅ Maximum durability
✅ Maximum availability
✅ Mission-critical data
✅ Enterprise applications
```

**Kosten:** Duurste  
**Risk:** ✅✅ Beschermd tegen zone EN regional disasters

**Visual:**
```
┌────────────────────────────┐       ┌─────────────────┐
│     Primary Region         │ Async │ Secondary Region│
│      West Europe           ├──────>│  North Europe   │
│ ┌──────┐ ┌──────┐ ┌──────┐│       │ ┌─────┐ ┌─────┐│
│ │Zone1 │ │Zone2 │ │Zone3 ││       │ │Copy1│ │Copy2││
│ │Copy1 │ │Copy2 │ │Copy3 ││       │ └─────┘ └─────┘│
│ └──────┘ └──────┘ └──────┘│       │    ┌─────┐     │
└────────────────────────────┘       │    │Copy3│     │
                                     │    └─────┘     │
                                     └─────────────────┘
```

## 📖 Read Access (RA-GRS / RA-GZRS)

### Wat is Read Access?

**Standaard GRS/GZRS:**
```
Primary Region:  Read + Write ✅
Secondary Region: ❌ Niet toegankelijk (alleen replication)
```

**Met Read Access (RA-GRS/RA-GZRS):**
```
Primary Region:   Read + Write ✅
Secondary Region: Read-only ✅
```

### Endpoint URLs

```csharp
// Primary endpoint
https://mystorageaccount.blob.core.windows.net

// Secondary endpoint (RA-GRS/RA-GZRS only)
https://mystorageaccount-secondary.blob.core.windows.net
```

### Use Cases

```
✅ Load balancing reads across regions
✅ Disaster recovery testing
✅ Geographic data distribution
✅ Reduced latency for distant users
```

### C# Voorbeeld

```csharp
var options = new BlobClientOptions();
options.GeoRedundantSecondaryUri = new Uri(
    "https://mystorageaccount-secondary.blob.core.windows.net"
);

var blobClient = new BlobClient(primaryUri, credential, options);

// SDK tries secondary if primary fails
// ⚠️ Will NOT retry if secondary returns 404
```

## 🔄 Changing Redundancy

### Kan Direct (No Downtime)

```bash
# LRS ↔ GRS
az storage account update --sku Standard_GRS

# LRS ↔ ZRS (in supported regions)
az storage account update --sku Standard_ZRS

# GRS ↔ GZRS
az storage account update --sku Standard_GZRS
```

**Instantly applied** - geen data copy nodig!

### Vereist Data Copy

Sommige conversies vereisen een **manual migration**:

```
LRS → ZRS (unsupported regions)
├── Gebruik AzCopy
├── Of: Azure Data Box
└── Of: Create new account + copy

Premium → Standard (different account type)
└── Must create new account
```

## 🔄 Failover

### Manual Failover

**Wanneer:**
```
Primary region is unavailable
└── Manually trigger failover
    └── Secondary becomes new primary
```

**Process:**
```bash
# Initiate failover
az storage account failover --name mystorageaccount

# After failover:
Old Primary (West Europe)   → Becomes Secondary
Old Secondary (North Europe) → Becomes Primary
```

**Considerations:**
```
⚠️ Data loss mogelijk (async replication)
⚠️ Downtime: ~1 hour
⚠️ DNS change required
⚠️ Last Sync Time kan gecheckt worden
```

### Niet Ondersteund

```
❌ Azure Files (NFS/SMB)
❌ BlockBlobStorage accounts
❌ Premium storage accounts
```

## 🌳 Hierarchical Namespace (Data Lake)

### Wat is het?

**Standard Blob Storage:**
```
Flat namespace:
/container/path/to/file.txt
     └── Simulated folders met slashes
```

**Hierarchical Namespace:**
```
True filesystem:
/container
  └── path
      └── to
          └── file.txt
           └── Real directories!
```

### Enable tijdens creatie

```bash
az storage account create \
  --enable-hierarchical-namespace true \
  --kind StorageV2
```

### Features

```
✅ Filesystem semantics
✅ Directory operations (rename, move)
✅ POSIX-compliant ACLs
✅ Optimized for big data analytics
✅ Compatible with Hadoop, Spark, etc.
```

### Beperkingen

```
❌ Cannot enable on existing accounts
❌ Cannot disable once enabled
❌ No failover support (GRS/GZRS)
❌ Lifecycle management limited
```

### Use Cases

```
✅ Data lakes
✅ Big data analytics
✅ Machine learning datasets
✅ Hadoop/Spark workloads
```

```

```

## 🎯 CLI Commands

### Create Storage Account

```bash
az storage account create \
  --name mystorageaccount \
  --resource-group MyResourceGroup \
  --location westeurope \
  --sku Standard_LRS \
  --kind StorageV2 \
  --access-tier Hot \
  --https-only true \
  --min-tls-version TLS1_2
```

### Update Storage Account

```bash
# Change redundancy
az storage account update \
  --name mystorageaccount \
  --sku Standard_GRS

# Change access tier
az storage account update \
  --name mystorageaccount \
  --access-tier Cool

# Enable hierarchical namespace (niet mogelijk!)
# Must create new account

# Add tags
az storage account update \
  --name mystorageaccount \
  --tags Environment=Production CostCenter=IT
```

### Get Properties

```bash
# Show account details
az storage account show \
  --name mystorageaccount \
  --query "loginServer"

# Get connection string
az storage account show-connection-string \
  --name mystorageaccount

# List all storage accounts
az storage account list \
  --resource-group MyResourceGroup \
  --output table
```

## 🎓 Samenvatting

### Key Points

1. **Storage Account** = Top-level namespace voor alle storage
2. **5 Types:** StorageV2 (⭐), Storage (legacy), BlobStorage (legacy), BlockBlobStorage (premium), FileStorage (premium)
3. **2 Performance Tiers:** Standard (HDD) vs Premium (SSD)
4. **4 Redundancy Options:** LRS, ZRS, GRS, GZRS
5. **Read Access:** RA-GRS en RA-GZRS voor secondary read
6. **Naming:** 3-24 chars, lowercase, globally unique
7. **Changing:** Redundancy instant, Type vereist nieuwe account

### Decision Guide

```
Nieuwe projecten:
└── StorageV2 + Standard + ZRS/GRS

High performance:
└── BlockBlobStorage + Premium_ZRS

Maximum durability:
└── StorageV2 + RA-GZRS

Cost-optimized:
└── StorageV2 + Standard_LRS + Cool/Archive tiers
```
