# 📦 Azure Blob Storage - Overzicht

## 🤔 Wat is Azure Blob Storage?

Azure Blob Storage is een **object storage** oplossing voor het opslaan van enorme hoeveelheden **ongestructureerde data** zoals:
- Text files
- Binary data (images, video's, audio)
- Documents
- Backups
- Log files
- Datasets voor analytics

**"Blob"** staat voor **Binary Large Object**.

## 🏗️ Hiërarchie & Structuur

Azure Blob Storage heeft drie niveaus:

```
Storage Account
└── Container (zoals een folder)
    └── Blob (het bestand)
```

### Visuele Representatie

```
┌─────────────────────────────────────┐
│  Storage Account: mystorageaccount  │
│  ├── Container: images              │
│  │   ├── Blob: logo.png             │
│  │   └── Blob: banner.jpg           │
│  ├── Container: documents           │
│  │   ├── Blob: report.pdf           │
│  │   └── Blob: invoice.docx         │
│  └── Container: backups             │
│      └── Blob: db-backup.bak        │
└─────────────────────────────────────┘
```

---

## 🌐 Endpoint Structuur

Elk blob heeft een unieke URL:

```
https://<storage-account>.blob.core.windows.net/<container>/<blob>
```

### Voorbeelden

```
https://mystorageaccount.blob.core.windows.net/images/logo.png
https://mystorageaccount.blob.core.windows.net/documents/report.pdf
https://mystorageaccount.blob.core.windows.net/backups/db-backup.bak
```

## 📊 Drie Resource Types

### 1️⃣ Storage Account

**Wat:** De top-level container voor al je storage resources.

**Kenmerken:**
- Unieke namespace in Azure
- Naam moet globaal uniek zijn (3-24 karakters)
- Bepaalt regio, redundancy, performance tier

**DNS naam moet geldig zijn:**
```
✅ mystorageaccount
✅ storage123
✅ mycompany-storage

❌ MyStorageAccount (hoofdletters)
❌ my_storage (underscores)
❌ storage-123- (eindigt met dash)
```

### 2️⃣ Container

**Wat:** Organiseert blobs, vergelijkbaar met een directory/folder.

**Kenmerken:**
- Unlimited aantal containers per storage account
- Unlimited aantal blobs per container
- Lowercase DNS naam (3-63 karakters)
- Geen dubbele dashes (--)

**Naamgeving voorbeelden:**
```
✅ images
✅ user-uploads
✅ backup-2024

❌ Images (hoofdletters)
❌ user--uploads (dubbele dashes)
❌ my_container (underscores)
```

### 3️⃣ Blob

**Wat:** Het daadwerkelijke bestand/object.

**Kenmerken:**
- Case-sensitive naam
- Mag niet eindigen met dot (.) of dash (-)
- Kan "virtual directories" simuleren met forward slashes

**Voorbeelden:**
```
✅ logo.png
✅ 2024/january/report.pdf (virtual directory)
✅ user_123_avatar.jpg
✅ MyFile.TXT (case-sensitive!)

❌ document. (eindigt met punt)
❌ file- (eindigt met dash)
```

## 🎨 Drie Blob Types

Azure Blob Storage ondersteunt drie verschillende blob types, elk geoptimaliseerd voor specifieke scenario's:

### 1️⃣ Block Blobs (Meest gebruikt) ⭐

**Gebruik voor:** Text en binary data (images, videos, documents)

**Kenmerken:**
- Maximum size: **190.7 TiB**
- Data wordt opgeslagen in blocks
- Optimaal voor upload/download van grote files
- Standaard keuze voor de meeste scenarios

**API Operatie:**
```http
PUT https://account.blob.core.windows.net/container/blob?comp=block&blockid=id
```

**Use Cases:**
```
✅ Images en video's
✅ Documents (PDF, Word, Excel)
✅ Application binaries
✅ Backups
✅ Website content
```

### 2️⃣ Append Blobs

**Gebruik voor:** Logging en audit scenarios

**Kenmerken:**
- Geoptimaliseerd voor **append operations**
- Data kan alleen toegevoegd worden (niet overschrijven)
- Ideaal voor log files
- Maximum size: **195 GiB**

**API Operatie:**
```http
PUT https://account.blob.core.windows.net/container/blob?comp=appendblock
```

**C# Voorbeeld:**
```csharp
AppendBlobClient appendBlobClient = containerClient.GetAppendBlobClient("logfile.txt");

// Read data
await appendBlobClient.AppendBlockAsync(memoryStream);
// Kan alleen appenden, niet overschrijven!
```

**Use Cases:**
```
✅ VM logs
✅ Application logging
✅ Audit trails
✅ Telemetry data
```

**Speciale Permission:**
- `Add` permission is **alleen** voor Append Blobs
- Andere blob types hebben dit niet

### 3️⃣ Page Blobs

**Gebruik voor:** Random access files en VM disks

**Kenmerken:**
- Maximum size: **8 TiB**
- Optimaal voor frequent random read/write
- Gebruikt voor Azure VM disks
- Opgeslagen in 512-byte pages

**API Operatie:**
```http
PUT https://account.blob.core.windows.net/container/blob?comp=page
```

**C# Voorbeeld:**
```csharp
var pageBlobClient = blobContainerClient.GetPageBlobClient("disk.vhd");

// Create empty page blob
pageBlobClient.Create(16 * 1024 * 1024 * 1024); // 16 GB

// Resize
pageBlobClient.Resize(32 * 1024 * 1024 * 1024); // 32 GB

// Write pages
pageBlobClient.UploadPages(dataStream, startingOffset);

// Read pages
var pageBlob = pageBlobClient.Download(new HttpRange(bufferOffset, rangeSize));
```

**Visual Representatie:**

```
Page Blob Structure:
┌─────────────────────────────────┐
│ Page 0 (512 bytes)              │
│ Page 1 (512 bytes)              │
│ Page 2 (512 bytes)              │
│ ...                             │
│ Page N (512 bytes)              │
└─────────────────────────────────┘
     ↓ Random Access ↓
┌─────────────────────────────────┐
│ Write to Page 100 directly      │
└─────────────────────────────────┘
```

**Use Cases:**
```
✅ VHD files voor Azure VMs
✅ VM data disks
✅ Database files (random access)
✅ Any scenario met frequent random I/O
```

## 📋 Blob Type Vergelijking

| Feature | Block Blob | Append Blob | Page Blob |
|---------|-----------|-------------|-----------|
| **Max Size** | 190.7 TiB | 195 GiB | 8 TiB |
| **Optimized For** | Upload/download | Append operations | Random access |
| **Write Pattern** | Overwrite | Append-only | Random write |
| **Use Case** | General purpose | Logging | VM disks |
| **Access Tiers** | ✅ All | ✅ Hot only | ✅ All |
| **API Endpoint** | `?comp=block` | `?comp=appendblock` | `?comp=page` |

## 🔄 ETag & Versioning

### ETag (Entity Tag)

**Wat:** Unieke identifier die verandert bij elke wijziging van de blob.

**Gebruik:**
- Concurrent access control
- Optimistic concurrency
- Cache validation

**Voorbeeld:**
```csharp
BlobProperties properties = await blobClient.GetPropertiesAsync();
string etag = properties.Value.ETag;

// Update alleen als ETag nog steeds hetzelfde is
BlobRequestConditions conditions = new BlobRequestConditions { IfMatch = etag };
await blobClient.UploadAsync(data, conditions);
```

**Scenario:**
```
User A: Leest blob (ETag: "abc123")
User B: Leest blob (ETag: "abc123")
User B: Update blob (ETag wordt: "def456")
User A: Probeert update (ETag: "abc123")
        → FAILS! ETag komt niet overeen
        → Voorkomt data loss
```

## 💰 Kosten Factoren

Azure Blob Storage kosten bestaan uit:

### 1. Storage Capacity
```
Hoeveel data je opslaat (GB/maand)
├── Hot tier: Duurder
├── Cool tier: Goedkoper
├── Cold tier: Nog goedkoper
└── Archive tier: Goedkoopst
```

### 2. Transactions
```
API calls (per 10,000 operations)
├── Write operations (duurder)
├── Read operations (goedkoper)
└── Delete/List operations
```

### 3. Data Transfer
```
Data uit Azure region (egress)
├── Eerste 100 GB/maand: Gratis
├── Daarna: Betaald per GB
└── Data IN (ingress): GRATIS! ✅
```

### 4. Additional Features
```
Optionele features
├── Geo-replication (GRS/GZRS)
├── Blob versioning
├── Soft delete
└── Encryption met customer keys
```

## 🎯 Wanneer Blob Storage Gebruiken?

### ✅ Gebruik Blob Storage voor:

- **Unstructured data:** Images, videos, logs
- **Large files:** Gigabytes tot terabytes
- **Direct browser access:** Via HTTPS URLs
- **Static website hosting**
- **Backup en archiving**
- **Data lakes voor analytics**
- **Media streaming**

### ❌ NIET gebruiken voor:

- **Relationele data** → Gebruik Azure SQL Database
- **Low-latency random access** → Gebruik Azure Premium SSD Disks
- **File shares met SMB protocol** → Gebruik Azure Files
- **Structured data met queries** → Gebruik Cosmos DB of Table Storage
- **Small frequent updates** → Consider Redis Cache

## 🔑 Key Takeaways

1. **Blob Storage = Object Storage** voor unstructured data
2. **Drie levels:** Storage Account → Container → Blob
3. **Drie blob types:** Block (algemeen), Append (logs), Page (VM disks)
4. **Unieke URLs** voor elke blob
5. **Access tiers** voor cost optimization (Hot/Cool/Cold/Archive)
6. **Redundancy options** voor high availability
7. **Multiple authentication** methoden (Shared Key, Entra ID, SAS)
8. **Schaalbaar** tot exabytes aan data
