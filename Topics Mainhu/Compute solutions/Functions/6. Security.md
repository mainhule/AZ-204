# Security

## Authorization Levels

Geeft aan welk type authorization key vereist is om het function endpoint te benaderen, via `code` parameter:

```
https://<APP_NAME>.azurewebsites.net/api/<FUNCTION_NAME>?code=<API_KEY>
```

### Levels

**🔓 Anonymous**  
Geen API key vereist.

**🔑 Function** (default)  
Een function-specifieke of host-wide API key is vereist.

**👑 Admin**  
De master key is vereist.

---

## Access Scopes

### Function Keys
Geven alleen toegang tot de specifieke functie waarvoor ze gedefinieerd zijn.

### Host Keys
Geven toegang tot alle functies binnen de function app.

**Master key:**
- Biedt administrative toegang tot runtime REST APIs
- Kan niet worden ingetrokken

**⚠️ Let op:**  
Als een function en een host key dezelfde naam delen, heeft de function key voorrang.

## Werken met Access Keys

**Base URL:**
```
https://management.azure.com/subscriptions/{subscriptionId}/resourceGroups/{resourceGroupName}/providers/Microsoft.Web/sites/{name}/{scope}/{host-or-function-name}/{action}?api-version=2022-03-01
```

**Scope:** Kan `functions` of `host` zijn.  
**Voor slots:** Voeg `/slots/{slot-name}/` toe vóór scope.

### Operaties

**Keys ophalen:**
```
POST - action: listkeys
```

**Keys maken of updaten:**
```
PUT - action: keys/{keyName}
```

**Keys verwijderen of intrekken:**
```
DELETE - action: /keys/{keyName}
```

## CORS Configureren

### Domain toevoegen aan allowed origins
```bash
az functionapp cors add \
    --allowed-origins https://contoso.com \
    --name MyFunctionApp \
    --resource-group MyResourceGroup
```

### Huidige allowed origins bekijken
```bash
az functionapp cors show \
    --name MyFunctionApp \
    --resource-group MyResourceGroup
```

## Managed Identity

Elke deployment slot / app heeft zijn eigen managed identity configuratie.

### REST Endpoint Reference

Een app met managed identity definieert twee environment variables voor een endpoint. Dit endpoint kan worden gebruikt om tokens aan te vragen voor toegang tot andere Azure services:

**Environment Variables:**
- `IDENTITY_ENDPOINT`: Endpoint waaruit apps tokens kunnen aanvragen
- `IDENTITY_HEADER`: (uuid) Gebruikt om server-side request forgery (SSRF) attacks te helpen voorkomen

### Endpoint Parameters

**Vereist:**
- `resource`
- `api-version`
- `X-IDENTITY-HEADER` (header)

**Optioneel:**
- `client_id`
- `principal_id`
- `mi_res_id`

Voor user-assigned identities, include één van de optionele properties; zonder dit wordt een system-assigned identity token aangevraagd.

### Voorbeeld Request

```http
GET {IDENTITY_ENDPOINT}?resource=https://vault.azure.net&api-version=2019-08-01&client_id=XXX
X-IDENTITY-HEADER: {IDENTITY_HEADER}
```

## Default (Host) Key Ophalen

De default (host) key kan gebruikt worden om elke HTTP triggered function in de function app te benaderen.

```bash
subName='<SUBSCRIPTION_ID>'
resGroup=AzureFunctionsContainers-rg
appName=glengagtestdocker
path=/subscriptions/$subName/resourceGroups/$resGroup/providers/Microsoft.Web/sites/$appName/host/default/listKeys?api-version=2018-11-01

az rest --method POST --uri $path --query functionKeys.default --output tsv
```
