# [Azure Key Vault](https://docs.microsoft.com/en-us/azure/key-vault/)

Endpoint: `https://vault.azure.net`

- Azure Key Vault slaat veilig secrets, keys en certificates op.
- Beschikbaar in twee tiers: **Standard** voor software encryption, **Premium** voor HSM-protected keys.
- Centraliseert security data om leaks te minimaliseren en het opslaan van gevoelige info in code te voorkomen.
- Biedt monitoring om key en secret toegang te volgen.
- Schaalt automatisch en waarborgt high availability door data replicatie.
- Automatiseert certificate taken.
- Integreert met andere Azure services voor disk en database encryption.

`az keyvault create --name <YourKeyVaultName> --resource-group $resourceGroup --location <YourLocation>`

Secret instellen: `az keyvault secret set --vault-name $myKeyVault --name "ExamplePassword" --value "hVFkk965BuUv"`

Secret ophalen (in _JSON_ formaat): `az keyvault secret show --name "ExamplePassword" --vault-name $myKeyVault` (`value` property bevat de secret waarde)

Secret versie ophalen: `GET {vaultBaseUrl}/secrets/{secret-name}/{secret-version}?api-version=7.4`

## [Security](https://learn.microsoft.com/en-us/azure/key-vault/general/security-features)

## Key operaties

Secrets roteren:

- `az keyvault key rotate`: handmatige rotatie.
- `az keyvault key rotation-policy`: geautomatiseerde rotatie (bijv. tijd).

Keys verwijderen:

- `az keyvault key delete`: zet key in soft delete state (indien ingeschakeld, of verwijdert het simpelweg)
- `az keyvault key purge`: verwijdert permanent soft deleted key (**alleen**)

### Access Model

- **Management plane**: voor het beheren van de Key Vault zelf
- **Data plane**: voor het werken met de data opgeslagen in de Key Vault

Beide planes gebruiken Azure Microsoft Entra ID voor authentication, en [RBAC](https://learn.microsoft.com/en-us/azure/key-vault/general/rbac-guide?tabs=azure-cli) voor authorization (access control). _Data plane_ gebruikt ook een [access policies](https://learn.microsoft.com/en-us/azure/key-vault/general/assign-access-policy?tabs=azure-portal) (legacy) voor authorization. Minimum standaard role voor het verlenen van management en data (policies) toegang: `Contributor`.

```sh
az keyvault set-policy --name myKeyVault --object-id <object-id> --secret-permissions <secret-permissions> --key-permissions <key-permissions> --certificate-permissions <certificate-permissions>
```

### Authentication

Key Vault is gekoppeld aan de Entra ID tenant van de subscription en alle callers moeten registreren in deze tenant en authenticeren om toegang te krijgen tot de key vault.

Voor applicaties zijn er twee manieren om een service principal te verkrijgen:

- Schakel een system-assigned **managed identity** in (aanbevolen) voor de applicatie. Met managed identity beheert Azure intern de service principal van de applicatie en authenticeert automatisch de applicatie met andere Azure services. Managed identity is beschikbaar voor applicaties gedeployed naar verschillende services.
- Als je geen managed identity kunt gebruiken, registreer je in plaats daarvan de applicatie bij je Entra ID tenant. Registratie creëert ook een tweede application object dat de app identificeert over alle tenants.

`var client = new SecretClient(new Uri("<YourVaultUri>"), new DefaultAzureCredential());`

Authentication met REST:

```http
PUT https://<your-key-vault-name>.vault.azure.net/keys/<your-key-name>?api-version=7.2 HTTP/1.1
Authorization: Bearer <access_token> # token verkregen van Microsoft Entra ID
```

Als Authorization token ontbreekt of afgewezen wordt:

```http
401 Not Authorized
WWW-Authenticate: Bearer authorization="…", resource="…"
```

De `WWW-Authenticate` header parameters zijn:

- `authorization`: OAuth2 authorization service adres.
- `resource`: Resource naam (`https://vault.azure.net`) voor de authorization request.

### Toegang beperken

Voor veilige, single-resource toegang tot Azure Key Vault secrets, gebruik System Managed Identities om het hardcoden van credentials te voorkomen. Het gebruik van managed identities of environment variables kan ze blootstellen in je code.

Beperk vault toegang tot specifieke IPs via **virtual network service endpoints**.

### Data Transit Encryption

Veilige communicatie via **HTTPS** en **TLS** (min 1.2).

**Perfect Forward Secrecy** (PFS - beschermt verbindingen tussen klant en cloud services door unieke keys) en RSA-based 2,048-bit encryption key lengths beveiligen verbindingen.

## [Certificates](https://learn.microsoft.com/en-us/azure/key-vault/certificates/quick-create-net)

Maak een access policy voor je key vault die certificate permissions verleent aan je gebruikersaccount:

```sh
az keyvault set-policy --name <your-key-vault-name> --upn user@domain.com --certificate-permissions delete get list create purge
```

Certificates opslaan en ophalen:

```cs
var client = new CertificateClient(new Uri($"https://{keyVaultName}.vault.azure.net"), new DefaultAzureCredential());

// Certificate aanmaken
var operation = await client.StartCreateCertificateAsync(certificateName, CertificatePolicy.Default);
await operation.WaitForCompletionAsync();

// Ophalen
var certificate = await client.GetCertificateAsync(certificateName);
```

## Best Practices

- Gebruik een aparte vault voor elke applicatie en environment (production, test, staging).
- Beperk vault toegang tot geautoriseerde applicaties en gebruikers. (`az keyvault set-policy --name <YourKeyVaultName> --object-id <PrincipalObjectId> --secret-permissions get list`)
- Maak regelmatig backups van je vault. (`az keyvault key backup --vault-name <YourKeyVaultName> --name <KeyName> --file <BackupFileName>`)
- Schakel logging en alerts in.
- Schakel **soft-delete** en **purge protection** in om secrets 7-90 dagen te bewaren en geforceerde verwijdering te voorkomen. Kosten zijn van toepassing voor HSM-keys in de laatste 30 dagen van gebruik. Operaties zijn uitgeschakeld op verwijderde objecten, en er zijn geen kosten van toepassing. (OPMERKING: _soft-delete_ verhoogt de beveiliging, maar _verhoogt ook storage kosten_!)

  ```sh
  az keyvault update --name <YourKeyVaultName> --enable-soft-delete true
  az keyvault update --name <YourKeyVaultName> --enable-purge-protection true
  ```

## [Disaster en recovery](https://learn.microsoft.com/en-us/azure/key-vault/general/disaster-recovery-guidance)

Redundancy: Data wordt meestal gerepliceerd binnen de primary region en naar een secondary region (behalve voor sommige landen waar data regulatie vereist om het in dezelfde region met ZRS te houden). Voor AKV Premium wordt data van HSMs gerepliceerd naar slechts twee regions. Als een primary Azure region niet beschikbaar wordt, worden requests automatisch omgeleid naar een secondary region. Merk op dat sommige regions geen failover ondersteunen en de key vault read-only wordt tijdens deze tijd. Gebruikers in deze regions moeten recovery plans voorbereiden.

## Disk Encryption ([Windows](https://learn.microsoft.com/en-us/azure/virtual-machines/windows/disk-encryption-key-vault?tabs=azure-portal), [Linux](https://learn.microsoft.com/en-us/azure/virtual-machines/linux/disk-encryption-key-vault?tabs=azure-portal))

```sh
az login

# Een resource group is een logische container waarin Azure resources worden gedeployed en beheerd.
az group create --name $resourceGroup --location eastus

# Maak een key vault aan in dezelfde region en tenant als de VMs die versleuteld moeten worden.
# De key vault zal gebruikt worden om disk encryption keys en secrets te controleren en beheren.
az keyvault create --name "<keyvault-id>" --resource-group $resourceGroup --location "eastus"

# Update de advanced access policies van de key vault
az keyvault update --name "<keyvault-id>" --resource-group $resourceGroup --enabled-for-disk-encryption "true"
# Schakelt de Microsoft.Compute resource provider in om secrets op te halen van deze key vault wanneer deze key vault gerefereerd wordt in resource creation, bijvoorbeeld bij het aanmaken van een virtual machine.
az keyvault update --name "<keyvault-id>" --resource-group $resourceGroup --enabled-for-deployment "true"
# Sta Resource Manager toe om secrets op te halen van de vault.
az keyvault update --name "<keyvault-id>" --resource-group $resourceGroup --enabled-for-template-deployment "true"

# Deze stap is optioneel. Wanneer een key encryption key (KEK) gespecificeerd wordt, gebruikt Azure Disk Encryption die key om de encryption secrets te wrappen voordat naar Key Vault te schrijven.
az keyvault key create --name "myKEK" --vault-name "<keyvault-id>" --kty RSA --size 4096

# Schakel disk encryption in:
## Optioneel gebruik KEK bij naam
az vm encryption enable -g $resourceGroup --name "myVM" --disk-encryption-keyvault "<keyvault-id>" --key-encryption-key "myKEK"
## Optioneel gebruik KEK bij url
## Verkrijg <kek-url>
## az keyvault key show --vault-name "<keyvault-id>" --name "myKEK" --query "key.kid"
## az vm encryption enable -g $resourceGroup --name "MyVM" --disk-encryption-keyvault "<keyvault-id>" --key-encryption-key-url <kek-url> --volume-type All
```

## [Logging](https://learn.microsoft.com/en-us/azure/key-vault/key-vault-insights-overview)

### [Key Vault monitoren met Azure Event Grid](https://learn.microsoft.com/en-us/azure/key-vault/general/event-grid-overview)

`Portal > All Services > Key Vaults > key vault > Events > Event Grid Subscriptions > + Event Subscription` en vul de details in inclusief naam, event types en endpoint (zoals een Azure Function).

```cs
[FunctionName("KeyVaultMonitoring")]
public static async Task<IActionResult> Run(
    [HttpTrigger(AuthorizationLevel.Function, "get", "post", Route = null)] HttpRequest req, ILogger log)
{
    var requestBody = await new StreamReader(req.Body).ReadToEndAsync();
    var eventGridEvent = EventGridEvent.Parse(new BinaryData(requestBody));

    switch(eventGridEvent.EventType)
    {
        case SystemEventNames.KeyVaultCertificateNewVersionCreated:
        case SystemEventNames.KeyVaultSecretNewVersionCreated:
            log.LogInformation($"Nieuwe Key Vault secret/certificate versie aangemaakt event. Data: {eventGridEvent.Data}"); break;
        case SystemEventNames.KeyVaultKeyNewVersionCreated:
            log.LogInformation($"Nieuwe Key Vault key versie aangemaakt event. Data: {eventGridEvent.Data}"); break;
        default:
            log.LogInformation($"Event Grid Event van type {eventGridEvent.EventType} kwam voor, maar het wordt niet verwerkt."); break;
    }

    return new OkResult();
}
```

## Werken met KeyVault

```cs
// Een secret ophalen
var secretClient = new SecretClient(vaultUri: new Uri(vaultUrl), credential: new DefaultAzureCredential());
KeyVaultSecret secret = await secretClient.GetSecretAsync("YourSecretName");

var keyClient = new KeyClient(vaultUri: new Uri(vaultUrl), credential: new DefaultAzureCredential());
// Een nieuwe key aanmaken
KeyVaultKey key = await keyClient.GetKeyAsync("YourKeyName");
// Data versleutelen en ontsleutelen met de key via CryptographyClient
CryptographyClient cryptoClient = keyClient.GetCryptographyClient(key.Name, key.Properties.Version);
EncryptResult encryptResult = cryptoClient.Encrypt(EncryptionAlgorithm.RsaOaep, Encoding.UTF8.GetBytes(plaintext));
DecryptResult decryptResult = cryptoClient.Decrypt(EncryptionAlgorithm.RsaOaep, encryptResult.Ciphertext);
```
