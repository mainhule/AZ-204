# [Microsoft Entra ID](https://learn.microsoft.com/en-us/entra/identity/)

Implementeert [OAuth 2.0](https://learn.microsoft.com/en-us/entra/identity-platform/v2-protocols) authorization protocol, waardoor third-party apps toegang kunnen krijgen tot web-hosted resources namens gebruikers. Deze resources hebben een unieke _application ID URI_.

## Microsoft Entra ID vs Role-Based Access Control (RBAC)

| Feature        | Entra ID                                                            | Azure RBAC                                                                                   |
| -------------- | ------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| **Doel**    | Authentication. Identity & Access Management                        | Authorization                                                                                |
| **Focus**      | Entra ID Resources                                                  | Azure Resources                                                                              |
| **Scope**      | Tenant                                                              | Management Group, Subscription, Resource Group, Resource                                     |
| **Roles**      | Global, User, Billing Admins; Custom roles; Meerdere roles per user | Owner, Contributor, Reader, User Access Admin; Custom roles (P1/P2); Meerdere roles per user |
| **Toegang Via** | Azure Portal, MS 365 Admin, Graph, PowerShell                       | Azure Portal, CLI, PowerShell, ARM templates, REST API                                       |
| **Pricing**    | Free, P1, P2 (Maandelijks betaald)                                      | Free (Met Azure subscription)                                                               |

## Use case: App Service web app die toegang heeft tot Microsoft Graph API (of andere service)

- Voor multi-tenant applicaties wordt een _application service principal_ gebruikt om permissions te verlenen. Dit stelt de app in staat om toegang te krijgen tot Microsoft Graph API resources over meerdere tenants zonder afhankelijk te zijn van een specifieke gebruikersidentiteit.
- Voor single-tenant scenario's waar de app alleen toegang nodig heeft tot resources binnen een specifieke tenant, zou een _Managed Identity_ geschikter zijn.
- Wanneer de app acties moet uitvoeren specifiek voor een individuele gebruiker (_on behalf of the user_), worden delegated permissions gebruikt, wat gebruikersauthenticatie en consent vereist.
- Als de permissions die de applicatie nodig heeft dynamisch kunnen veranderen op basis van runtime condities, zou het gebruik van _Entra ID roles en policies_ geschikter zijn.
- Voor short-lived operaties die geen persistente permissions vereisen, kunnen _token-based of key-based temporary access methods_ geschikter zijn.

## Application Registration

Alle applicaties _moeten [registreren bij Entra ID](https://learn.microsoft.com/en-us/azure/app-service/configure-authentication-provider-aad?tabs=workforce-tenant)_ om identity en access management te delegeren: `Portal > app > 'Authentication' > 'Add identity provider' > stel provider in op Microsoft > 'Add'`. Dit creëert een application object en een globally unique ID (app/client ID).

- **Application Object**: Bevindt zich in de Entra ID tenant waar de app geregistreerd is. Het dient als de _global representation_ van je applicatie voor gebruik over alle tenants. Dit object heeft:

  - Een 1:1 relatie met de Software Application.
  - Een 1:N relatie met _Service Principal Objects_, wat betekent dat één Application Object meerdere corresponderende _Service Principal Objects_ kan hebben.

- **[Service principals](https://learn.microsoft.com/en-us/azure/active-directory/develop/app-objects-and-service-principals?tabs=browser) Objects**: Dit zijn _local representations_ binnen elke tenant (gebruik **Enterprise applications** pagina in de Azure portal om te beheren). Ze zijn afgeleid van het Application Object en komen in drie types:
  - **Application**: Aangemaakt wanneer een app resource access permissions krijgt.
  - **Managed Identity**: Automatisch aangemaakt wanneer ingeschakeld. Het verleent toegang maar is niet direct aanpasbaar.
  - **Legacy**: Voor apps aangemaakt vóór moderne registratiemethoden, beperkt tot de tenant waar aangemaakt.

Wijzigingen aan je application object beïnvloeden ook de bijbehorende service principals alleen in de home tenant. Het verwijderen van de application verwijdert ook de home tenant service principal, maar het herstellen van dat application object zal de service principals niet herstellen.

Lijst service principals gekoppeld aan een app: `az ad sp list --filter "appId eq '{AppId}'"`

- `<Permission-Id>=Scope`: Delegated permissions
- `<Permission-Id>=Role`: Application permissions

## [Permissions (Scopes)](https://learn.microsoft.com/en-us/azure/active-directory/develop/permissions-consent-overview)

De app specificeert vereiste permissions met de `scope` query parameter, die het resource type definieert. Indien niet gespecificeerd, is de standaard resource Microsoft Graph. Bijvoorbeeld, `scope=User.Read` is hetzelfde als `https://graph.microsoft.com/User.Read`.

| Permission types | Delegated permissions                                                    | Application permissions                    |
| ---------------- | ------------------------------------------------------------------------ | ------------------------------------------ |
| Toegangscontext   | Krijg toegang namens een gebruiker (een ingelogde gebruiker is aanwezig)             | Krijg toegang zonder een gebruiker (ingelogde gebruiker) |
| Types apps    | Web / Mobile / single-page app (SPA)                                     | Web / Daemon / Background services         |
| Andere namen      | Scopes / OAuth2 permission scopes                                        | App / App-only permissions roles           |
| Wie kan consent geven  | - Gebruikers kunnen consent geven voor hun data<br>- Admins kunnen consent geven voor alle gebruikers | Alleen admin kan consent geven                     |
| Consent methoden  | Static of Dynamic                                                        | Alleen Static                                |

`az ad app permission add --id {appId} --api {apiID} --api-permissions {permissionId}={Scope,Role}`

- Scope: Definieert **wat de applicatie mag doen** namens een gebruiker.
- Role: Definieert meer geprivilegieerde **operaties die de applicatie kan uitvoeren**, vaak zonder een gebruiker

### [Consent](https://learn.microsoft.com/en-us/azure/active-directory/manage-apps/user-admin-consent-overview)

- **Static user consent**: Vereist dat alle permissions gespecificeerd worden in de Azure portal tijdens app registratie. Gebruikers of admins worden gevraagd om consent als dit niet eerder verleend is. Problemen: vereist lange lijsten van permissions en het van tevoren kennen van alle resources.
- **Incremental (Dynamic) user consent**: Staat toe dat permissions geleidelijk aangevraagd worden. Scopes kunnen tijdens runtime gespecificeerd worden zonder voorafgaande definitie in Azure portal.
- **Admin consent**: nodig voor high-privilege permissions. Admins autoriseren apps om toegang te krijgen tot privileged data. Vereist static permissions registratie. `az ad app permission admin-consent`

Individueel user consent aanvragen:

```http

client_id=00001111-aaaa-2222-bbbb-3333cccc4444

&scope=https%3A%2F%2Fgraph.microsoft.com%2Fcalendars.read%20https%3A%2F%2Fgraph.microsoft.com%2Fmail.send
&state=12345
```

## [Conditional Access](https://learn.microsoft.com/en-us/azure/active-directory/conditional-access/overview) (Premium P1 tier)

- Vraag aanvullende verificatie (bijv. tweede wachtwoord of vingerafdruk) wanneer gebruikers inloggen
- Gebruik een middle tier om een "challenge" op te lossen gepresenteerd door API
- [Multi-Factor Authentication](https://learn.microsoft.com/en-us/azure/active-directory/authentication/concept-mfa-licensing) (**alle Microsoft 365 plans**). Wanneer [Security Defaults](https://learn.microsoft.com/en-us/azure/active-directory/fundamentals/security-defaults) is ingeschakeld, wordt MFA geactiveerd voor **alle gebruikers**. Om MFA alleen op specifieke gebruikers toe te passen, _schakel Security Defaults uit_.
- Risk-based policies (vereisen Entra ID Identity Protection - **Premium P2** tier)
- Device restrictions (ingeschreven in Microsoft's Intune service)
- Bepaalde fysieke locaties of IP ranges

Wanneer Conditional Access licenties verlopen, blijven policies actief maar kunnen niet worden bijgewerkt.

Apps hoeven niet aangepast te worden, tenzij ze silent of indirect services toegang nodig hebben, of on-behalf-of flow.

## MSAL (Microsoft Authentication Library)

Maakt veilige toegang mogelijk tot verschillende APIs, met een unified API over platforms.

- Verkrijgt tokens voor gebruikers of applicaties (indien van toepassing).
- Beheert token cache en vernieuwt tokens automatisch.
- Helpt bij het specificeren van de gewenste audience voor applicatie sign-in.
- Helpt bij applicatie setup vanuit configuratiebestanden.
- Biedt actionable exceptions, logging en telemetry voor troubleshooting.

### [Authentication flows](https://learn.microsoft.com/en-us/azure/active-directory/develop/msal-authentication-flows)

| Flow               | Application Type | Use Case                                          | Token Acquisition Method                    |
| ------------------ | ---------------- | ------------------------------------------------- | ------------------------------------------- |
| Authorization code | Beide             | SPA, Native, Web Apps                             | Wisselt een authorization code voor een token |
| Client credentials | Confidential     | Daemon, Backend                                   | App Secret/Certificate                      |
| On-behalf-of       | Beide             | Service-to-Service, Service-to-API, Microservices | Gebruikt een bestaand token om een ander te krijgen       |
| Device code        | Public           | IoT, CLI                                          | Pollt het endpoint totdat gebruiker authenticeert |
| Implicit           | Public           | Legacy SPAs                                       | Token in URI fragment                       |
| Integrated Windows | Beide             | Intranet Apps                                     | Auto auth op domain / Entra ID-joined PCs   |
| Interactive        | Public           | User Interactive Apps                             | Vereist gebruikersactie                        |
| Username/password  | Beide             | Legacy, Testing                                   | Direct met Credentials                     |

- **Public client applications**: User-facing apps zonder het vermogen om secrets veilig op te slaan. Ze interacteren met web APIs namens de gebruiker.
- **Confidential client applications**: Server-based apps en daemons die secrets veilig kunnen beheren. Elke instantie onderhoudt een unieke configuratie, inclusief identifiers en secrets.

### Werken met MSAL

Bij het bouwen van web apps of public client apps die een broker vereisen, zorg ervoor dat je de `redirectUri` instelt. Deze URL wordt gebruikt door de identity provider om security tokens terug te sturen naar je applicatie.

Entra ID authenticatie integreren in een ASP.NET Core applicatie:

```cs
builder.Services.AddAuthentication(OpenIdConnectDefaults.AuthenticationScheme)
  .AddMicrosoftIdentityWebApp(builder.Configuration.GetSection("AzureAd"));

builder.Services.AddRazorPages()
  .AddMicrosoftIdentityUI();

// OpenIdConnectDefaults.AuthenticationScheme: Schakelt OpenID Connect authenticatie in, beste voor OAuth 2.0 en Single Sign-On (SSO).
// JwtBearerDefaults.AuthenticationScheme: Gebruikt voor het authenticeren van APIs via JSON Web Tokens (JWT), geschikt voor stateless en schaalbare APIs.
// CookieAuthenticationDefaults.AuthenticationScheme: Gebruikt cookies voor session-based authenticatie, optimaal voor traditionele web apps die gebruikerssessies server-side beheren.
// Custom Authentication Scheme: Staat aangepaste string identifiers toe voor authentication middleware, ideaal voor gespecialiseerde of unieke authenticatie scenario's.
```

```cs
// Log gebruikers in de Microsoft Azure public cloud in met hun werk- en schoolaccounts of persoonlijke Microsoft accounts.
IPublicClientApplication app = PublicClientApplicationBuilder.Create(clientId).Build();
```

## [Application manifest](https://learn.microsoft.com/en-us/azure/active-directory/develop/reference-app-manifest)

Een Entra ID application manifest configureert de identity en attributen van een app, en faciliteert OAuth authorization en user consent. Het dient als een mechanisme voor het bijwerken van het application object in het Microsoft identity platform.

- `signInAudience`:

  - `AzureADMyOrg` - Gebruikers met een Microsoft werk- of schoolaccount in de Microsoft Entra tenant van mijn organisatie (bijvoorbeeld single tenant)
  - `AzureADMultipleOrgs` - Gebruikers met een Microsoft werk- of schoolaccount in de Microsoft Entra tenant van elke organisatie (bijvoorbeeld multi-tenant)
  - `AzureADandPersonalMicrosoftAccount` - Gebruikers met een persoonlijk Microsoft account, of een werk- of schoolaccount in de Microsoft Entra tenant van elke organisatie
  - `PersonalMicrosoftAccount` - Persoonlijke accounts die gebruikt worden om in te loggen op services zoals Xbox en Skype.

- `groupMembershipClaims`: (_Tenant-specific_) Groups claim uitgegeven in access token die de app verwacht. Groups blijven bestaan zelfs nadat de bijbehorende app verwijderd is.

  - "None"
  - "SecurityGroup" (zal security groups en Entra ID roles bevatten)
  - "ApplicationGroup" (deze optie bevat alleen groups die toegewezen zijn aan de applicatie)
  - "DirectoryRole" (krijgt de Entra ID directory roles waarvan de gebruiker lid is)
  - "All" (dit krijgt alle security groups, distribution groups en Entra ID directory roles waarvan de ingelogde gebruiker lid is).

- [`appRoles`](https://learn.microsoft.com/en-us/azure/active-directory/develop/howto-add-app-roles-in-apps) (_Application-specific_): Verzameling van roles die een app kan declareren. Gedefinieerd in de app registratie en wordt ermee verwijderd. Komt overeen met `Role` in `--api-permissions`

  ```jsonc
  "appRoles": [{
      "allowedMemberTypes": [ "User" ],
      "value": "ReadOnly" // verwachte waarde van de roles claim in het token, die moet overeenkomen met de string in de applicatiecode zonder spaties.
  }]
  ```

- `oauth2Permissions`: Specificeert de verzameling OAuth 2.0 permission scopes die de web API (resource) app blootstelt aan client apps. Komt overeen met `Scope` in `--api-permissions`.

- `oauth2AllowImplicitFlow` - Of de web app implicit flow access tokens kan aanvragen (`oauth2AllowIdTokenImplicitFlow` voor ID tokens). ⭐: SPAs, bij gebruik van Implicit Grant Flow.

## ASP.NET Core Authorization: Werken met Roles, Claims en Policies

- [**Policies**](https://learn.microsoft.com/en-us/aspnet/core/security/authorization/policies?view=aspnetcore-3.1): Een policy is een functie die naar de identity van een gebruiker kan kijken en beslissen of ze geautoriseerd zijn om een bepaalde actie uit te voeren.
- [**Roles**](https://learn.microsoft.com/en-us/aspnet/core/security/authorization/roles?view=aspnetcore-3.1): Een role vertegenwoordigt een groep gebruikers die bepaalde privileges hebben zoals gedefinieerd door de role.
- [**Claims**](https://learn.microsoft.com/en-us/aspnet/core/security/authorization/claims?view=aspnetcore-3.1): Een claim is een name-value pair dat representeert wat het subject is, niet wat het subject kan doen.

```cs
// Startup.cs
public void ConfigureServices(IServiceCollection services)
{
    // Definieer policies
    services.AddAuthorization(options =>
    {
        options.AddPolicy("ClientsOnly", policy =>
        {
            policy.RequireAuthenticatedUser(); // Vereist dat de gebruiker geauthenticeerd is
            policy.RequireRoles("PrivateClient", "CorporateClient"); // Vereist EEN van deze vermelde roles
            policy.RequireClaim("SubscriptionTier", "free", "basic", "premium"); // Vereist EEN van de waarden voor SubscriptionTier
        });
        options.AddPolicy("FreeloadersOnly", policy =>
        {
            policy.RequireAuthenticatedUser();
            policy.RequireRole("PrivateClient");
            policy.RequireClaim("SubscriptionTier", "free");
        });
        options.AddPolicy("EmployeeOnly", policy => policy.RequireClaim("EmployeeNumber")); // Vereist EmployeeNumber claim
        options.AddPolicy("AdminOnly", policy => policy.RequireRole("Administrator")); // Vereist Administrator role
    });
}

// LoginController.cs
[HttpPost]
public async Task<IActionResult> Login(LoginViewModel model)
{
  // Checks weggelaten voor beknoptheid
  var user = await _userManager.FindByNameAsync(model.Username);
  var claim = new Claim("EmployeeNumber", "123");
  await _userManager.AddClaimAsync(user, claim);
}

[Authorize(Policy = "ClientsOnly")] // Sta alleen premium clients toe
public class AdminController : Controller { }
```
