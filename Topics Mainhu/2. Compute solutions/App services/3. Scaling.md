# Scaling

Instellingen zijn van toepassing op alle apps in je App Service Plan.

## Types Scaling

### 📅 Manual Scaling (Basic+)
Voor eenmalige events (bijvoorbeeld: X uitvoeren op deze datum)

### 📈 Autoscale (Standard+)
Voor voorspelbare veranderingen in applicatie load:
- Op basis van schema's (elke X dagen/weken/maanden)
- Op basis van resources

### ⚡ Automatic Scaling (PremiumV2+)
Zoals autoscale, maar voorkomt **cold start** problemen met:
- **Pre-warmed** instances
- **Always ready** instances

```bash
az appservice plan update --name $appServicePlanName --resource-group $resourceGroup \
    # Automatic scaling inschakelen
    --elastic-scale true --max-elastic-worker-count <YOUR_MAX_BURST> \
    # Automatic scaling uitschakelen
    --elastic-scale false
```

## Horizontal Scaling

Het toevoegen/verwijderen van virtual machines.

### 🔼 Scale Out (VM instances verhogen)
- Wordt getriggerd als **één** van de regels wordt voldaan

### 🔽 Scale In (VM instances verlagen)
- Wordt getriggerd als **alle** regels worden voldaan

## Vertical Scaling

Scale up/down - wanneer je het App Service Plan wijzigt

## ⚠️ Flapping

Een loop conditie waarbij een scale event zijn tegenhanger triggert in een serie van wisselende events.

## Scaling Rule instellen

1. Switch de web app naar Standard App Service Plan (voor Autoscale heb je Premium nodig)
2. Activeer autoscaling voor de Web App
3. Maak een scaling rule
4. Stel een scaling condition in
