# Diagnostics en Monitoring

## Diagnostics Log Types

| Type | Platform | Locatie | Opmerkingen |
|------|----------|---------|-------------|
| **Application logging** | Windows, Linux | App Service file system en/of Azure Storage blobs | Voor debugging van issues (bugs of onverwacht gedrag) binnen applicatie code |
| **Web server logging** | Windows | App Service file system of Azure Storage blobs | Raw HTTP request data. Voor diagnose van connectiviteit, HTTP errors (`404`), en server-level issues (`5xx`) |
| **Detailed Error Messages** | Windows | App Service file system | Kopieën van .htm error pages die naar de client browser zouden zijn gestuurd |
| **Failed request tracing** | Windows | App Service file system | Gedetailleerde tracering van gefaalde requests |
| **Deployment logging** | Windows, Linux | App Service file system | Logs voor wanneer je content publiceert naar een app |

### Belangrijke opmerkingen

⏰ **App Service file system** optie is voor tijdelijke debugging en schakelt zichzelf uit na 12 uur

💾 **Blob** optie is voor long-term logging, bevat extra informatie. Alleen voor .NET apps

🔒 `AppServiceFileAuditLogs` en `AppServiceAntivirusScanAuditLogs` zijn alleen beschikbaar voor Premium+

## Logging configureren

```bash
az webapp log config \
    --application-logging {azureblobstorage, filesystem, off} \
    --name MyApp \
    --resource-group MyResourceGroup
```

## Log Files benaderen

### Linux/Custom Containers
```
https://$appName.scm.azurewebsites.net/api/logs/docker/zip
```
ZIP file bevat console output logs voor zowel docker host als docker container.

### Windows Apps
```
https://$appName.scm.azurewebsites.net/api/dump
```

## Log Streaming

### Via Azure Portal
Navigeer naar je app en selecteer **Log stream**.

Logs geschreven naar `.txt`, `.log`, of `.htm` files in `/home/LogFiles` (of `D:\home\LogFiles` voor Windows apps) worden gestreamd.

⚠️ **Let op:** Sommige logs kunnen out of order verschijnen door buffering.

### Via CLI

```bash
# HTTP logs streamen
az webapp log tail --provider http --name MyApp --resource-group MyResourceGroup

# Errors streamen
az webapp log tail --filter Error --name MyApp --resource-group MyResourceGroup # filter op woord Error
az webapp log tail --only-show-errors --name MyApp --resource-group MyResourceGroup
```

## Monitoring Apps

### Metrics

Metrics worden gebruikt over **alle instances van het plan** (niet een enkele app!):
- CPU Percentage
- Memory Percentage
- Data In
- Data Out

**Voorbeeld:**
```
Metric: CPU Percentage
Resource: <AppServicePlanName>
```

```bash
az monitor metrics list \
    --resource $app_service_plan_resource_id \
    --metric "Percentage CPU" \
    --time-grain PT1M \
    --output table
```

### Verschil CPU Time vs CPU Percentage

**CPU Time:**
- Waardevol voor apps op Free of Shared plans
- Quota's zijn ingesteld op basis van CPU minuten gebruik van de app

**CPU Percentage:**
- Waardevol voor apps op Basic+
- Geeft inzicht in gebruik over schaalbare instances

## Health Checks

Health Check pingt het gespecificeerde pad elke minuut. Als een instance niet reageert met een geldige status code na 10 requests:
1. Wordt gemarkeerd als unhealthy
2. Wordt verwijderd uit de load balancer
3. Als het herstelt, wordt het teruggeplaatst in de load balancer
4. Als het een uur unhealthy blijft, wordt het vervangen (alleen voor Basic+)

### Voor Private Endpoints

Check of `x-ms-auth-internal-token` request header gelijk is aan de hashed waarde van `WEBSITE_AUTH_ENCRYPTION_KEY` environment variable.

Je moet eerst features zoals IP restrictions, client certificates, of Virtual Network gebruiken om applicatie toegang te beperken.

### Health Check configureren

```bash
az webapp config set \
    --health-check-path /api/health \
    --resource-group MyResourceGroup \
    --name MyApp
```
