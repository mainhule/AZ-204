# 💾 Persistence (Gegevenspersistentie)

## 🤔 Wat is Persistence?

**Persistence** betekent dat je **bestanden en data kunt opslaan** die blijven bestaan, zelfs als:
- Je app herstart
- Er een nieuwe instance wordt opgestart
- Er updates worden gedaan

**Zonder persistence:** Alle bestanden die je opslaat zijn weg na een herstart!

---

## 📂 Drie Manieren van Storage in App Service

### 1️⃣ Tijdelijke Storage (Niet-persistent)
**Wat:** Bestanden verdwijnen bij herstart
```
/tmp/myfile.txt → Na herstart: WEG! ❌
```

### 2️⃣ Persistent Storage (Standaard `/home`)
**Wat:** Bestanden blijven bestaan
```
/home/myapp/data.txt → Na herstart: BLIJFT! ✅
```

### 3️⃣ Azure Storage Mounts (Externe storage)
**Wat:** Verbind Azure Storage als folder
```
/mnt/myfiles → Verbonden met Azure Files/Blobs
```

---

## 🏠 Persistent Storage (Standaard `/home` Directory)

### Hoe werkt het?

**Voor Linux Containers (standaard AAN):**
```
Je App Service
├── /home/           ← Persistent storage (blijft bestaan)
│   ├── site/        ← Je applicatie code
│   ├── data/        ← Je eigen data
│   └── LogFiles/    ← Logs (altijd persistent)
├── /tmp/            ← Tijdelijk (verdwijnt bij herstart)
└── /var/            ← Tijdelijk (verdwijnt bij herstart)
```

### Praktisch Voorbeeld

**Scenario:** Je upload een PDF bestand

```csharp
// ✅ GOED: Opslaan in /home (blijft bestaan)
var path = "/home/site/uploads/document.pdf";
await File.WriteAllBytesAsync(path, fileBytes);

// App herstart...
// Bestand is er nog steeds! ✅

// ❌ FOUT: Opslaan in /tmp (verdwijnt)
var path = "/tmp/document.pdf";
await File.WriteAllBytesAsync(path, fileBytes);

// App herstart...
// Bestand is weg! ❌
```

### Delen tussen Instances

Als je app scaled naar **meerdere instances:**

```
Instance 1: Schrijft naar /home/data.txt
Instance 2: Kan /home/data.txt LEZEN ✅
Instance 3: Kan /home/data.txt LEZEN ✅
```

**Alle instances delen dezelfde `/home` directory!**

### Persistent Storage Uitschakelen

**Waarom uitschakelen?**
- Custom containers die eigen storage hebben
- Performance (lokale disk is sneller)
- Je gebruikt alleen externe storage

```bash
az webapp config appsettings set \
    --resource-group MyResourceGroup \
    --name MyApp \
    --settings WEBSITES_ENABLE_APP_SERVICE_STORAGE=false
```

**Effect:**
```
WEBSITES_ENABLE_APP_SERVICE_STORAGE=false
→ /home wordt NIET-PERSISTENT (verdwijnt bij herstart)
→ /home/LogFiles blijft WEL persistent (voor diagnostics)
```

## 💿 Local Cache (Windows Only)

### Wat is Local Cache?

**Probleem:** `/home` zit op netwerk storage → Kan soms traag zijn

**Oplossing:** Kopieer `/home` naar lokale disk van de server

```
Zonder Local Cache:
App → Netwerk → /home (Azure Storage) 📡 (langzamer)

Met Local Cache:
App → Lokale Disk → /home (kopie) 💨 (sneller)
```

### Hoe inschakelen?

```bash
az webapp config appsettings set \
    --resource-group MyResourceGroup \
    --name MyApp \
    --settings WEBSITE_LOCAL_CACHE_OPTION=Always
```

### ⚠️ Beperkingen

❌ **NIET ondersteund voor:**
- Function Apps
- Containerized App Service apps (Linux/Windows)
- Apps met custom storage mounts

✅ **WEL ondersteund voor:**
- Windows App Service (built-in runtimes)
- Read-heavy workloads

### Gedrag

```
Bij deployment:
1. Nieuwe code wordt geüpload naar netwerk /home
2. Local cache wordt geüpdatet
3. App herstart met nieuwe cache

Bij herstart:
1. Local cache blijft intact
2. App start sneller (geen netwerk IO)
```

## 🔗 Azure Storage Mounten als Local Share

### 🤔 Waarom Azure Storage Mounten?

**Probleem:** `/home` heeft beperkte ruimte (meestal 1-10 GB)

**Oplossing:** Verbind externe Azure Storage als folder in je app

**Use Cases:**
- Grote file uploads (video's, PDFs)
- Gedeelde data tussen meerdere apps
- Data die los staat van je app lifecycle

### Twee Opties

| Type | Read/Write | Platform | Gebruik |
|------|-----------|----------|---------|
| **Azure Files** | ✅ Read/Write | Windows + Linux | Shared files, databases |
| **Azure Blobs** | 📖 Read-only | Linux alleen | Static content, backups |

---

## 📋 Azure Files Mount (Read/Write)

### Scenario: Upload Portal

Je bouwt een portal waar gebruikers bestanden uploaden:

**Setup:**
```bash
# 1. Maak Storage Account
az storage account create \
    --name mystorageaccount \
    --resource-group MyResourceGroup \
    --sku Standard_LRS

# 2. Maak File Share
az storage share create \
    --name uploads \
    --account-name mystorageaccount \
    --quota 100

# 3. Mount in App Service
az webapp config storage-account add \
    --resource-group MyResourceGroup \
    --name MyApp \
    --custom-id UploadsMount \
    --storage-type AzureFiles \
    --share-name uploads \
    --account-name mystorageaccount \
    --access-key "your-access-key" \
    --mount-path /mnt/uploads
```

### Gebruik in Code

```csharp
// Upload bestand naar mounted storage
[HttpPost("upload")]
public async Task<IActionResult> Upload(IFormFile file)
{
    // Mount path: /mnt/uploads
    var filePath = $"/mnt/uploads/{file.FileName}";
    
    using (var stream = new FileStream(filePath, FileMode.Create))
    {
        await file.CopyToAsync(stream);
    }
    
    return Ok("File saved to Azure Files!");
}

// Lijst bestanden
[HttpGet("files")]
public IActionResult ListFiles()
{
    var files = Directory.GetFiles("/mnt/uploads");
    return Ok(files);
}
```

**Voordelen:**
- ✅ Onbeperkte storage (tot 100 TB per share)
- ✅ Shared tussen meerdere apps
- ✅ Read + Write mogelijk
- ✅ Backups apart van app

## 📋 Azure Blobs Mount (Read-only)

### Scenario: Static Content

Je hebt grote static files (product catalogs, images):

**Setup:**
```bash
# 1. Maak Blob Container
az storage container create \
    --name static-content \
    --account-name mystorageaccount \
    --public-access off

# 2. Mount als read-only in Linux App
az webapp config storage-account add \
    --resource-group MyResourceGroup \
    --name MyApp \
    --custom-id StaticContent \
    --storage-type AzureBlob \
    --share-name static-content \
    --account-name mystorageaccount \
    --access-key "your-access-key" \
    --mount-path /mnt/static
```

### Gebruik in Code

```csharp
// Lees static content
[HttpGet("catalog/{filename}")]
public IActionResult GetCatalog(string filename)
{
    var filePath = $"/mnt/static/catalogs/{filename}";
    
    if (!System.IO.File.Exists(filePath))
        return NotFound();
    
    var bytes = System.IO.File.ReadAllBytes(filePath);
    return File(bytes, "application/pdf");
}
```

**⚠️ Read-only betekent:**
```csharp
// ✅ Lezen werkt
var content = File.ReadAllText("/mnt/static/file.txt");

// ❌ Schrijven geeft ERROR
File.WriteAllText("/mnt/static/file.txt", "data"); // Exception!
```

## 🎯 Mount Configuratie Opties

### Alle Parameters

```bash
az webapp config storage-account add \
    --resource-group MyResourceGroup \
    --name MyApp \
    --custom-id UniqueIdentifier \        # Unieke naam voor deze mount
    --storage-type AzureFiles \           # AzureFiles of AzureBlob
    --share-name myshare \                # Share/container naam
    --account-name mystorageaccount \     # Storage account naam
    --access-key "key" \                  # Access key (of --sas-token)
    --mount-path /mnt/mydata              # Waar te mounten in app
```

### Mount Beheren

```bash
# Lijst alle mounts
az webapp config storage-account list \
    --resource-group MyResourceGroup \
    --name MyApp

# Update mount
az webapp config storage-account update \
    --resource-group MyResourceGroup \
    --name MyApp \
    --custom-id UniqueIdentifier \
    --mount-path /mnt/newpath

# Verwijder mount
az webapp config storage-account delete \
    --resource-group MyResourceGroup \
    --name MyApp \
    --custom-id UniqueIdentifier
```

## ⚠️ Belangrijke Beperkingen

### ❌ Gebruik NIET voor:

**1. Databases**
```
❌ SQLite database op mounted storage → Corrupt data!
❌ MongoDB op Azure Files → Performance issues!

✅ Gebruik: Azure SQL, Cosmos DB
```

**2. Apps die File Locks nodig hebben**
```
❌ Concurrent writes met locking
❌ Applications die exclusive file access verwachten

✅ Gebruik: Voor read-only of sequential writes
```

**3. Deze Paths**
```
❌ /                  → Root directory
❌ /home             → Conflicts met default storage
❌ /tmp              → Bedoeld voor tijdelijke files

✅ /mnt/mydata       → Safe custom path
✅ /data             → Safe custom path
```

### ⚠️ Gedrag bij Changes

**Mount toevoegen/wijzigen:**
```
Change mount → App restart! 🔄
```

**Storage failover:**
```
Azure Storage fails over → Mount werkt niet meer!
→ App moet remounten of herstarten
```

**Storage account verwijderen:**
```
1. Verwijder eerst de mount configuratie
2. Dan pas storage account verwijderen
```

## � Security & Networking

### Storage Firewall

**Probleem:** Azure Storage firewall blokkeert App Service

**Oplossing:** Service Endpoints of Private Endpoints

```bash
# Service Endpoint
az webapp vnet-integration add \
    --resource-group MyResourceGroup \
    --name MyApp \
    --vnet MyVnet \
    --subnet AppSubnet

# Storage firewall: Allow subnet
az storage account network-rule add \
    --account-name mystorageaccount \
    --subnet AppSubnet
```

### Access Keys vs SAS Tokens

**Access Key (volledige toegang):**
```bash
--access-key "VeryLongKey123..."
```
⚠️ Regenereren van key → Mount werkt niet meer!

**SAS Token (beperkte toegang):**
```bash
--sas-token "?sv=2021-06-08&ss=f&srt=sco&sp=rwdlc..."
```
✅ Kan expiration hebben
✅ Beperkte permissions mogelijk

## 💰 Kosten

### App Service Storage (gratis)

```
Persistent Storage (/home):
- Inbegrepen bij App Service plan
- Beperkt tot 1-10 GB (afhankelijk van plan)
- Geen extra kosten
```

### Azure Storage (apart gefactureerd)

```
Azure Files:
- Storage: ~$0.06 per GB/maand
- Transactions: ~$0.002 per 10,000
- Data transfer: Variabel

Azure Blobs:
- Storage: ~$0.02 per GB/maand (Hot tier)
- Transactions: ~$0.0004 per 10,000
- Data transfer: Variabel
```

**Let op:** Zet storage in dezelfde region als app om data transfer kosten te vermijden!

## ✅ Best Practices

### 1. Regional Colocation

```bash
# ✅ GOED: Zelfde region
App Service: West Europe
Storage Account: West Europe
→ Sneller, geen data transfer kosten

# ❌ SLECHT: Verschillende regions
App Service: West Europe
Storage Account: East US
→ Langzamer, data transfer kosten!
```

### 2. Access Key Rotatie

```bash
# Gebruik key1 in productie
--access-key "key1"

# Rotatie zonder downtime:
1. Regenereer key2
2. Update mount met key2
3. Wacht tot propagated
4. Regenereer key1 (nu veilig)
```

### 3. Storage Choice

**Kies Azure Files als:**
- ✅ Je read/write nodig hebt
- ✅ Je meerdere apps toegang wilt geven
- ✅ Je traditionele file operations doet

**Kies Azure Blobs als:**
- ✅ Je alleen lezen nodig hebt
- ✅ Je grote amounts van data hebt
- ✅ Je lagere kosten wilt

**Kies Persistent Storage als:**
- ✅ Data size < 10 GB
- ✅ Data is app-specific
- ✅ Eenvoud belangrijker dan flexibiliteit

### 4. Backup Strategy

```
App Backups (via App Service):
✅ /home directory
❌ Mounted Azure Storage (NIET inbegrepen!)

→ Maak aparte backups voor Azure Storage!

az backup ...  # Voor Storage Account
```

## 🎓 Samenvatting

### Quick Decision Guide

**Heb je < 10 GB nodig?**
→ Gebruik default `/home` (persistent storage) ✅

**Heb je > 10 GB nodig?**
→ Mount Azure Files ✅

**Heb je alleen read access nodig voor grote files?**
→ Mount Azure Blobs ✅

**Heb je database nodig?**
→ GEEN mounted storage! Gebruik Azure SQL/Cosmos DB ✅

**Wil je fastest performance?**
→ Local Cache (Windows only) ✅

### Key Takeaways

1. **Default `/home`** is persistent en shared tussen instances
2. **Azure Storage mounts** geven unlimited storage
3. **Azure Files** = read/write, **Azure Blobs** = read-only
4. **NOOIT** databases op mounted storage!
5. **Storage costs** zijn apart van App Service
6. **Same region** voor beste performance en lagere kosten
