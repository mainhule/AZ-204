# Custom Handlers

Lightweight web servers die interacteren met de Azure Functions host. Ze kunnen worden geïmplementeerd in elke taal die HTTP primitives ondersteunt.

## Hoe werkt het?

Wanneer een event plaatsvindt:
1. Azure Functions host forwarded de request naar de custom handler's web server
2. De web server voert de functie uit
3. Retourneert de output voor verdere verwerking door de host

⏱️ **Belangrijk:** De custom handler web server moet binnen 60 seconden starten.

---

## Application Structure

### 📁 Vereiste Bestanden

**host.json**
- Gebruik `customHandler.description.defaultExecutablePath` property om het executable path en arguments in te stellen

**local.settings.json**
- Stel `FUNCTIONS_WORKER_RUNTIME` in op "custom" voor lokale development

**Command / Script / Executable**
- Draait een web server

**function.json**
- Voor elke functie (**binnen een folder die overeenkomt met de functie naam**)
- Voorbeeld: `MyFunctionName/function.json`

---

## HTTP-only Function

`customHandler.enableForwardingHttpRequest` laat je HTTP-triggered function direct de originele HTTP request en response afhandelen in plaats van Azure's custom payloads.

### Voordelen
✅ Je handler gedraagt zich meer als een traditionele web server  
✅ Handig voor eenvoudigere setups zonder extra bindings of outputs

### Beperkingen
⚠️ Azure Functions is geen volwaardige reverse proxy  
⚠️ Sommige features zoals HTTP/2 en WebSockets worden niet ondersteund

**Denk eraan:** Het geeft je handler raw toegang tot de HTTP actie zonder Azure's middleman tussenkomst.
