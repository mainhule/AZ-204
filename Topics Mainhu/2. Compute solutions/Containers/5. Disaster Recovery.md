# Disaster Recovery

In het geval van een volledige regio outage heb je twee strategieën:

## 🔧 Manual Recovery

### Optie 1: Deploy naar nieuwe regio
Handmatig deployen naar een nieuwe regio wanneer de huidige regio uitvalt.

### Optie 2: Wacht op herstel
Wacht tot de regio herstelt, en deploy dan handmatig alle environments en apps opnieuw.

**Nadelen:**
- ⏰ Downtime tijdens herstel
- 👤 Vereist handmatige actie
- 📉 Geen automatische failover

---

## 🛡️ Resilient Recovery

Deploy je container apps **vooraf** naar meerdere regio's.

### Architectuur

```
┌─────────────────────────────────────┐
│   Azure Front Door / Traffic Manager │
│   (Traffic routing & load balancing) │
└──────────┬──────────────┬───────────┘
           │              │
   ┌───────▼─────┐  ┌────▼────────┐
   │   Region 1  │  │   Region 2  │
   │ (Primary)   │  │ (Secondary) │
   │             │  │             │
   │ Container   │  │ Container   │
   │ Apps        │  │ Apps        │
   └─────────────┘  └─────────────┘
```

### Setup Stappen

#### 1. Deploy apps naar meerdere regio's

```bash
# Primary regio
az containerapp create \
    --name MyApp \
    --resource-group MyResourceGroup \
    --environment prod-eastus \
    --location eastus \
    --image myapp:latest

# Secondary regio
az containerapp create \
    --name MyApp \
    --resource-group MyResourceGroup \
    --environment prod-westus \
    --location westus \
    --image myapp:latest
```

#### 2. Azure Front Door configureren

```bash
# Front Door profile maken
az afd profile create \
    --profile-name MyFrontDoor \
    --resource-group MyResourceGroup \
    --sku Standard_AzureFrontDoor

# Endpoint maken
az afd endpoint create \
    --endpoint-name myendpoint \
    --profile-name MyFrontDoor \
    --resource-group MyResourceGroup

# Origin group maken
az afd origin-group create \
    --origin-group-name myorigingroup \
    --profile-name MyFrontDoor \
    --resource-group MyResourceGroup

# Origins toevoegen (beide regio's)
az afd origin create \
    --origin-name eastus-origin \
    --origin-group-name myorigingroup \
    --profile-name MyFrontDoor \
    --resource-group MyResourceGroup \
    --host-name myapp-eastus.azurecontainerapps.io \
    --priority 1 \
    --weight 50

az afd origin create \
    --origin-name westus-origin \
    --origin-group-name myorigingroup \
    --profile-name MyFrontDoor \
    --resource-group MyResourceGroup \
    --host-name myapp-westus.azurecontainerapps.io \
    --priority 1 \
    --weight 50
```

#### 3. Health probes configureren

```bash
az afd origin-group update \
    --origin-group-name myorigingroup \
    --profile-name MyFrontDoor \
    --resource-group MyResourceGroup \
    --probe-path /health \
    --probe-protocol Https \
    --probe-interval-in-seconds 30
```

## Voordelen Resilient Recovery

### ✅ Automatische Failover
Traffic wordt automatisch gerouteerd naar gezonde regio's.

### ✅ Geen Downtime
Gebruikers ervaren minimale tot geen downtime.

### ✅ Load Balancing
Traffic wordt verdeeld over meerdere regio's voor betere performance.

### ✅ Health Monitoring
Automatische monitoring van endpoint health.

---

## Traffic Management Strategieën

### Priority-based Routing
```bash
# Primary regio heeft priority 1
--priority 1 --weight 100

# Secondary regio heeft priority 2
--priority 2 --weight 100
```

Traffic gaat normaal naar primary, failover naar secondary bij uitval.

### Weighted Routing
```bash
# 50/50 verdeling
--priority 1 --weight 50
--priority 1 --weight 50
```

Traffic wordt evenredig verdeeld over beide regio's.

### Geographic Routing
Route gebruikers naar dichtstbijzijnde regio voor lagere latency.

## Best Practices

### 🔄 Synchronisatie
Zorg dat beide deployments identiek zijn:
- Zelfde image versie
- Zelfde configuratie
- Zelfde secrets

### 📊 Monitoring
Monitor beide regio's continu:
```bash
az monitor log-analytics query \
    --workspace $WORKSPACE_ID \
    --analytics-query "ContainerAppSystemLogs_CL | where TimeGenerated > ago(1h)" \
    --out table
```

### 🧪 Testen
Test failover scenario's regelmatig:
- Simuleer regio uitval
- Verifieer traffic routing
- Test recovery procedures

### 💾 Data Replicatie
Zorg voor data replicatie tussen regio's:
- Cosmos DB multi-region writes
- Storage account geo-redundancy
- Database replicatie

## Health Check Endpoint

Implementeer health check voor elke app:

```csharp
app.MapGet("/health", () => Results.Ok(new { 
    status = "healthy",
    region = Environment.GetEnvironmentVariable("REGION")
}));
```

## Kosten Overwegingen

💰 **Dubbele resources:**
- Resources draaien in beide regio's
- Ongeveer 2x de kosten

💰 **Front Door kosten:**
- Routing en health monitoring
- Data transfer kosten

⚖️ **Trade-off:**
- Hogere kosten vs. betere availability
- Business kritieke apps: resilient recovery
- Non-kritieke apps: manual recovery
